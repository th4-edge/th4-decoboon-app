## 二、详细诊断与修复方案

### BUG-01【P0】多个页面缺少路由参数时抛出未捕获 Promise 异常

#### 现象

直接访问需要 `id` / `projectId` / `stageId` 参数的页面时，控制台抛出：



```
Uncaught (in promise) ProviderRequestError: projectId不能为空

&#x20;   at providerFailure (src/core/http.ts:56:10)

&#x20;   at success (src/core/http.ts:91:16)
```

受影响页面及错误信息：



| 页面                     | 错误信息               | 页面表现                          |
| ---------------------- | ------------------ | ----------------------------- |
| `pages/project/plan`   | `projectId不能为空`    | 白屏，仅标题 "施工计划"                 |
| `pages/project/invite` | `projectId不能为空` ×2 | 页面直接显示原始错误文本 "projectId 不能为空" |
| `pages/project/album`  | `projectId不能为空`    | 空状态正常展示，但控制台报错                |
| `pages/report/daily`   | `projectId不能为空`    | 空状态正常展示，但控制台报错                |
| `pages/accept/edit`    | `stageId不能为空`      | 白屏，仅标题 "阶段验收"                 |

#### 根因

这些页面的 `onLoad` 中直接读取 `q?.id || ''` 后**未做空值校验**，立即调用 `load()` 发起 API 请求。空字符串被传给后端，后端返回 `ProviderRequestError`，而前端 `load()` 函数没有 `try/catch` 包裹（或 catch 不完整），导致 Promise 异常未被捕获。

**反例（project/plan.vue 第 22-28 行）：**



```
onLoad((q) => {

&#x20; if (!isLoggedIn()) uni.reLaunch({ url: P.login })

&#x20; id.value = q?.id || ''

&#x20; load()  // ← 未判断 id 是否为空，未 try/catch

})

async function load() {

&#x20; const \[p, s, t] = await Promise.all(\[

&#x20;   projectApi.info(id.value),      // id 为空时直接报错

&#x20;   projectApi.stages(id.value),

&#x20;   scheduleApi.tasks(id.value)

&#x20; ])

&#x20; // ...

}
```

**正面参考（stage/detail.vue 和 task/detail.vue 已正确实现）：**



* 缺少参数时显示 "加载失败 + 参数名不能为空 + 重新加载" 按钮，而非白屏或抛异常。

#### 修复方案

统一在 `onLoad` 中增加参数守卫，并给 `load()` 加 try/catch。以 `project/plan.vue` 为例：



```
// src/pages/project/plan.vue

const loadError = ref('')

onLoad((q) => {

&#x20; if (!isLoggedIn()) uni.reLaunch({ url: P.login })

&#x20; id.value = q?.id || ''

&#x20; if (!id.value) {

&#x20;   loadError.value = '缺少项目参数，请从项目列表进入'

&#x20;   return

&#x20; }

&#x20; void load()

})

async function load() {

&#x20; loading.value = true

&#x20; loadError.value = ''

&#x20; try {

&#x20;   const \[p, s, t] = await Promise.all(\[

&#x20;     projectApi.info(id.value),

&#x20;     projectApi.stages(id.value),

&#x20;     scheduleApi.tasks(id.value),

&#x20;   ])

&#x20;   project.value = p || null

&#x20;   stages.value = \[...s].sort((a, b) => a.sort - b.sort)

&#x20;   tasks.value = t

&#x20; } catch (error) {

&#x20;   loadError.value = error instanceof Error ? error.message : '加载失败，请稍后重试'

&#x20; } finally {

&#x20;   loading.value = false

&#x20; }

}
```

模板中增加错误态：



```
\<view v-if="loadError" class="jz-card plan\_\_error">

&#x20; \<text>{{ loadError }}\</text>

&#x20; \<button class="jz-btn jz-btn--plain jz-btn--sm" @tap="load">重新加载\</button>

\</view>
```

**需同步修复的文件清单：**



* `src/pages/project/plan.vue`

* `src/pages/project/invite.vue`（已有 `.catch` 但仍有 2 处未捕获，需检查是否有其他 API 调用未包裹）

* `src/pages/project/album.vue`

* `src/pages/report/daily.vue`

* `src/pages/accept/edit.vue`

**建议：** 在 `src/core/http.ts` 的 `post()` 函数中增加全局 unhandledrejection 监听，或在 `App.vue` 中注册 `onUnhandledRejection`，将所有未捕获 Promise 异常统一上报并提示，避免静默失败。

### BUG-02【P1】customer/detail 页面 Vue 警告：Fragment 根节点导致 id 属性无法继承

#### 现象

访问客户详情页（带有效 id）时，控制台出现两次警告：



```
\[Vue warn]: Extraneous non-props attributes (id) were passed to component

but could not be automatically inherited because component renders fragment

or text root nodes.

&#x20; at \<Detail>

&#x20; at \<AsyncComponentWrapper>

&#x20; ...
```

#### 根因

`src/pages/customer/detail.vue` 第 344-346 行的模板有**两个并列根节点**：



```
\<template>

&#x20; \<view v-if="!customer && !booted" class="cd\_\_loading">...\</view>

&#x20; \<view v-else-if="customer" class="cd">...\</view>

\</template>
```

`v-if` / `v-else-if` 使组件成为 Fragment（多根节点）。uni-app 路由将 URL 查询参数 `id` 作为非 prop 属性传递给页面组件，Vue 无法确定将其继承到哪个根节点，因此抛出警告。

#### 修复方案

**方案 A（推荐）：包裹单一根节点**



```
\<template>

&#x20; \<view class="cd">

&#x20;   \<view v-if="!customer && !booted" class="cd\_\_loading">\<JzSkeleton :rows="6" />\</view>

&#x20;   \<view v-else-if="customer" class="cd\_\_body">

&#x20;     \<!-- 原有内容 -->

&#x20;   \</view>

&#x20; \</view>

\</template>
```

**方案 B：显式禁止属性继承**



```
// 在 \<script setup> 中添加

defineOptions({ inheritAttrs: false })
```

方案 A 更符合 uni-app 页面单根节点的约定，且不影响样式（外层 `.cd` 可保留原有布局）。推荐方案 A。

### BUG-03【P1】首页快捷入口文字重叠

#### 现象

首页 "快捷入口" 区域，7 个入口的文字标签横向重叠在一起，显示为连续文本 "客户管理合同签约邀请成员我的团队财务总览消息通知报价项目库"，图标与文字错位。

#### 根因

`src/styles/home.scss` 第 18 行：



```
.home\_\_quick { width: 20%; display: flex; flex-direction: column; align-items: center; margin-bottom: 20rpx; }

.home\_\_quick-label { margin-top: 10rpx; font-size: \$jzb-font-xs; color: \$jzb-text-2; }
```

问题：



1. `width: 20%` 固定 5 列，但 boss 角色有 7 个快捷入口，第二行仅 2 个，布局尚可；

2. **关键问题**：`.home__quick-label` 未设置 `width: 100%` 和 `text-align: center`，在 H5 端 `<text>` 元素为 inline 行为，当 flex 容器 `align-items: center` 时，文字宽度由内容决定，但多个相邻 flex item 的文字在某些渲染条件下发生重叠；

3. 缺少 `white-space: nowrap` 和 `overflow: hidden`，4 字标签在窄列中可能溢出。

#### 修复方案



```
.home\_\_quick {

&#x20; width: 25%;              // 改为 4 列，7 个入口时第二行 3 个，更均衡

&#x20; display: flex;

&#x20; flex-direction: column;

&#x20; align-items: center;

&#x20; margin-bottom: 20rpx;

&#x20; transition: transform \$jzb-duration-fast \$jzb-ease-out;

}

.home\_\_quick-label {

&#x20; width: 100%;             // 关键：占满容器宽度

&#x20; margin-top: 10rpx;

&#x20; font-size: \$jzb-font-xs;

&#x20; color: \$jzb-text-2;

&#x20; text-align: center;      // 关键：文字居中

&#x20; white-space: nowrap;     // 防止换行

&#x20; overflow: hidden;

&#x20; text-overflow: ellipsis;

}
```

同时检查 `ROLE_ACTIONS` 中 boss 角色的入口数量，建议控制在每行 4 个、总数不超过 8 个，避免拥挤。

### BUG-04【P2】部分页面缺少参数时白屏或无限加载

#### 现象



| 页面                      | 表现                                |
| ----------------------- | --------------------------------- |
| `pages/project/detail`  | 仅显示标题 "工地详情"，正文完全空白               |
| `pages/report/edit`     | 仅显示标题 "进度汇报"，正文完全空白               |
| `pages/finance/project` | 永久显示 "项目财务数据加载中 / 请稍后重试"，无超时也无错误态 |

#### 根因

与 BUG-01 同源：`onLoad` 未校验参数，API 请求失败后页面既无错误提示也无空状态，停留在初始空白或 loading 状态。

`finance/project` 额外问题：加载状态 `loading` 可能在 API 报错后未被重置为 `false`，导致永久 loading。

#### 修复方案

参照 BUG-01 的统一修复模式，为这三个页面增加：



1. `onLoad` 参数空值守卫；

2. `load()` 的 try/catch/finally（finally 中必须重置 `loading.value = false`）；

3. 模板中增加 `v-if="loadError"` 错误态卡片 + 重试按钮。

### BUG-05【P2】favicon.ico 404（全站持续）

#### 现象

每个页面加载时控制台出现：



```
Failed to load resource: the server responded with a status of 404 (Not Found)
```

Network 面板显示请求 `GET http://127.0.0.1/favicon.ico` 返回 404。

#### 根因

`index.html` 中未声明 `<link rel="icon">`，浏览器自动请求 `/favicon.ico`，但项目 `src/static/` 或根目录下没有该文件，nginx 返回 404。

#### 修复方案

二选一：

**方案 A（推荐）：添加品牌 favicon**



1. 在 `src/static/` 下放置 `favicon.ico`（或 SVG 图标）；

2. 在 `index.html` 的 `<head>` 中添加：



```
\<link rel="icon" type="image/svg+xml" href="/static/favicon.svg" />
```

**方案 B（快速消除 404）：** 在 `index.html` 中添加空图标：



```
\<link rel="icon" href="data:,">
```

### BUG-06【P2】Vite HMR WebSocket 握手失败（开发环境）

#### 现象



```
WebSocket connection to 'ws://127.0.0.1/' failed:

Error during WebSocket handshake: Unexpected response code: 200

\[vite] Direct websocket connection fallback.
```

#### 根因

nginx 反代 Vite Dev Server 时，未配置 WebSocket 升级头（`Upgrade` / `Connection`），导致 HMR 的 WebSocket 连接被 nginx 当作普通 HTTP 请求处理，返回 200 而非 101 Switching Protocols。Vite 自动降级为直连（`ws://localhost:5173`），功能不受影响但控制台持续报错。

#### 修复方案

在 nginx 配置中为 Vite 代理增加 WebSocket 支持：



```
location / {

&#x20;   proxy\_pass http://127.0.0.1:5173;

&#x20;   proxy\_http\_version 1.1;

&#x20;   proxy\_set\_header Upgrade \$http\_upgrade;

&#x20;   proxy\_set\_header Connection "upgrade";

&#x20;   proxy\_set\_header Host \$host;

}
```

如果 nginx 配置不可改，可在 `vite.config.ts` 中设置 `server.hmr.port` 指向直连端口，并接受降级方案（仅 dev 环境影响，不影响生产构建）。

### BUG-07【P3】密码框未包含在 form 中（可访问性警告）

#### 现象



```
\[DOM] Password field is not contained in a form:
```

#### 根因

`src/pages/auth/login.vue` 使用 `<input>` 而非 `<form>` 包裹，浏览器密码管理器提示可访问性问题。uni-app 小程序端不支持 `<form>` 的标准行为，H5 端可优化。

#### 修复方案

低优先级。可在 H5 端用 `<view>` 模拟 form 语义，或添加 `aria-*` 属性。小程序端无需处理。

## 五、通用防御建议



1. **建立页面参数守卫规范**：所有需要 `id` 参数的页面，在 `onLoad` 中必须先校验，空值时显示错误态而非发起请求。建议封装 `useRequiredParam(name)` composable。

2. **统一 load 函数模式**：所有异步加载函数必须 `try/catch/finally`，finally 中重置 loading，catch 中设置 loadError。

3. **全局未捕获异常监听**：在 `App.vue` 或 `main.ts` 中注册 `window.onunhandledrejection`，统一上报并 toast 提示，避免静默失败。

4. **页面单根节点约定**：uni-app 页面模板必须有单一根节点，禁止 Fragment（v-if/v-else 并列根节点）。

5. **CI 增加 console 错误检测**：集成 e2e 测试时断言 `console.error` 为空，防止回归。
