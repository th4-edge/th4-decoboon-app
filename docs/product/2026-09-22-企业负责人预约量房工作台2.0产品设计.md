# 装得清 · 企业负责人预约量房工作台 2.0

> 状态：P0 设计冻结，按现有 Measure 状态事实实现  
> 日期：2026-09-22  
> 依据：用户 2026-09-22 裁决、`SCN-001`、`BR-001`、`CAP-002`  
> 约束：设计师线下没有“接单/拒单”动作；不重做状态机，不新增“已接单/上门中”人工状态。

## 0. 定位

预约量房页不是登记表，而是企业负责人的：

- 经营看板：今天有多少预约、多少待派、多少完成。
- 调度台：按业务员分组，快速找到客户和责任人。
- 异常处理台：待派单、预约超时、待交设计优先露出。
- 业务入口：约定量房、改派设计师、联系客户、查看量房记录。

中小装企的核心目标：响应快、派得准、转化高。

## 1. 事实与状态边界

主对象：`Property + Measure`。客户用于经营漏斗和负责人关系，房屋用于承载量房、设计、报价和项目。

现有事实：

- `Measure.scheduledAt`：房屋级预约时间。
- `Measure.completedAt`：实际完成时间。
- `Measure.designer`：设计责任人。
- `Measure.executor`：实际执行人。
- `MeasureStatus`：`Scheduled / Completed / Cancelled`。

派生状态：

| 派生状态 | 判断 | 页面文案 |
| --- | --- | --- |
| NotScheduled | 无预约、无完成 | 未预约量房 |
| Unassigned | 已预约、未指派设计责任人 | 已预约·待派单 |
| Scheduled | 已预约、已指派、未完成、未超时 | 已预约·待上门 |
| Overdue | 预约超过 4 小时未完成 | 预约逾期 |
| CompletedPendingHandoff | 已完成、48 小时内未交设计 | 量房完成·待交设计 |
| HandoffRisk | 已完成超过 48 小时未交设计 | 待交设计 |
| DesignStarted | 已形成设计诉求或方案 | 已交设计 |

不新增人工“接单/拒单/上门中”；上门和完成继续由真实动作形成事实。

## 2. 信息架构

App P0：

```text
预约量房首页
  ├── 全企业经营看板
  ├── 异常待办
  ├── 业务员分组
  ├── 状态条件
  ├── 客户/房屋列表
  └── 约定量房 / 改派 / 联系 / 查看记录

人员绩效考核页
  └── 业务员量房业绩
        ├── 预约量、完成量、预约率、完成率、逾期率、待指派
        ├── 日增 / 昨日 / 近7日增 / 月增
        └── 后续排名与趋势
```

P1：预约详情强化、排期日历、派单辅助。

P2：渠道漏斗、签约转化、异常原因分析、智能推荐。

## 3. 首页经营看板

固定展示全企业口径，不随业务员分组变化：

| 指标 | 口径 |
| --- | --- |
| 今日预约 | 今天 `scheduledAt` 且未取消 |
| 待派单 | 已预约、未完成、设计责任人为空 |
| 近7日预约 | 含今天在内滚动 7 天 `scheduledAt` |
| 已完成 | `completedAt` 非空 |
| 完成率 | 已完成 / 已预约 |
| 交设计率 | 已交设计 / 已完成 |

日期维度：

- 日增：今天预约、今天完成
- 昨日：昨天预约、昨天完成
- 近7日增：滚动 7 天预约、完成
- 月增：本月预约、完成

不以 `completedAt` 冒充实际上门时间，不在缺少到达事实时计算“准时率”。准时率进入 P1，需新增实际到达/签到时间后实现。

## 4. 异常待办

横向标签：

- 待派单
- 预约逾期
- 待交设计
- 未预约量房

点击后直接过滤列表。异常排序优先于普通列表。

## 5. 业务员分组列表

- 左侧仅按客户负责人（业务员）分组；不再同时铺客户来源、执行设计师。
- 选中业务员后，右侧只保留作业指标：客户数、待预约、已预约、已完成、风险。
- 列表条件：全部、待派单、未预约、已预约、逾期、已完成、待交设计。
- 卡片保留客户、房屋、来源、业务员、预约/完成时间、设计责任人、执行人、照片数量和下一步。
- 当前卡片品牌色高亮；支持放大客户区和返回经营概览。

## 6. 快捷动作

| 派生状态 | 主按钮 | 次按钮 |
| --- | --- | --- |
| 未预约 | 约定量房 | 联系客户 |
| 待派单 | 立即派单 | 联系客户 |
| 已预约待上门 | 查看预约 | 联系客户 |
| 预约逾期 | 改约/查看预约 | 联系客户 |
| 已完成 | 查看量房记录 | 客户 360 |
| 待交设计 | 查看记录/提醒交设计 | 客户 360 |

“立即派单”复用客户详情的更换设计责任人能力；不新增独立派单主对象。

## 7. 权限

- BOSS：全企业预约量房、经营看板、业务员分组、全部客户。
- 店长：门店数据范围。
- 团队负责人：团队数据范围。
- 业务员：本人客户和量房推进。
- 设计师：执行本人负责的量房，不在本页做全企业经营分析。
- 跨企业、跨门店、非参与人必须服务端拒绝。

## 8. 验收

- 全企业统计与业务员分组列表使用不同口径：顶部不随分组变化，分组指标只随选中业务员变化。
- 待派单、逾期、待交设计、未预约条件过滤正确。
- 立即派单进入客户详情并打开设计责任人选择器。
- 联系客户调用系统拨号，不泄露其他客户电话。
- 量房记录、改约、客户 360 路径可达。
- 日期窗口在月初、跨月、今天/昨天无数据时正确。
- 不出现“已接单”“上门中”“准时率”等缺少事实支撑的状态或指标。
- 其他角色数据范围正确，账务、合同、成本、应收应付、结算和利润不变。
