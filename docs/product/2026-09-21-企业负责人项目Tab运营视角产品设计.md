# 装得清小程序 · 企业负责人「项目」Tab 运营视角产品设计

> 状态：用户已确认（v1.1；4 项待确认问题已裁决，见 §15）
> 范围：微信小程序 BOSS 视角的底部「项目」Tab（`src/pages/project/list.vue`）与其聚合接口 `project/project/overview`
> 日期：2026-09-21
> 依据：`DEC-001`、`BR-002`、`BR-003`、`BR-004`、`MET-002`、`GAP-003`、`GAP-005`
> 姊妹设计：`2026-09-20-企业负责人首页产品设计.md`、`2026-09-21-企业负责人合同签约与履约产品设计.md`

## 0. 结论摘要

把「项目」Tab 从**一张施工进度列表**，升级为**企业负责人的在建项目经营台账**。

同一份数据要同时回答负责人的五个经营问题：

- **盘子**：现在有多少个项目在跑，压着多少合同额。
- **钱**：工程款收得怎么样，谁欠着，逾期多少。
- **交付**：每个工地干到哪一步，计划什么时候完，有没有拖期。
- **风险**：哪些项目需要我介入，原因是什么，下一步该谁做。
- **赚不赚**：这一单成本齐不齐、毛利是多少（仅负责人可见，成本不完整时明确显示「成本未完整」）。

页面结构统一采用 **经营指标带 + 状态分段 + 经营卡片**，与「客户经营」（`pages/customer/list.vue`）、「报价谈单」（`quote/pages/detail.vue`）、「合同履约档案」保持同一套「先结论、再明细、再下钻」的运营视角写法。

> 重要边界：本次**不新增业务对象、不改变项目状态机、不改变金额与成本口径**。所有指标均由既有 `Project / ProjectContract / Receivable / Receipt / ContractChange / StockMovement` 与 `BusinessAlertContext` 的既有预警规则聚合得出。

## 1. 为什么要改

### 1.1 现状（2026-09-21 代码事实）

| 环节 | 现状 | 对负责人的影响 |
| --- | --- | --- |
| 项目 Tab | `pages/project/list.vue`：筛选 + 卡片（封面、名称、社区/面积、设计/经理、进度、当前阶段、合同额） | 只有「施工进度视角」，看不到钱和风险 |
| 首页项目区块 | `BossWorkbench.attentionProjects`：只展示**有预警**的项目，最多 4 条 | 定位正确，但**看不到全部项目** |
| 经营预警 | `BusinessAlertContext`：逾期应收 / 停工与工期逾期 / 材料超领 / 变更率异常 | 能力已有，却只在首页和预警页露出，未落到项目台账 |
| 合同履约 | `project/contract/info`、`contract/workbench` | 合同数据与项目列表断开，负责人要在多个页面之间跳 |
| 财务 | `finance/project` 独立页 | 回款与项目列表互不引用 |
| 成本毛利 | `ProjectCostContext` 已统一口径，`costComplete` 存在 | 项目列表不展示成本完整性，负责人看不到「这一单赚不赚」 |

### 1.2 问题（负责人视角）

1. **看不见盘子**：项目 Tab 没有公司级汇总，负责人无法一眼判断「在施规模」。
2. **看不见钱**：合同额有，但已收、未收、逾期、回款率全在财务页。
3. **看不见风险**：首页只有 4 条风险卡，第 5 个出问题的项目在项目 Tab 里和正常项目长得一模一样。
4. **看不见利润**：项目卡片不体现成本是否完整，负责人无法判断「这单是不是亏的」。
5. **排序不合经营习惯**：默认按 `projectId` 倒序（最新录入优先），而不是「风险优先 / 金额优先 / 回款最慢优先」。

### 1.3 目标

- 负责人在**一个 Tab**里完成「看盘子 → 找风险 → 定动作 → 下钻」的闭环。
- 项目 Tab 展示**全部项目**（与首页「只展示风险项目」不重复、不冲突），风险项目在列表中显性分层。
- 指标全部由服务端一次聚合返回，前端只负责按角色、状态和异常态渲染，不在前端拼装金额口径。
- 非负责人角色**保持现有施工列表体验**，不被负责人运营字段干扰。

## 2. 真实业务场景

默认样本：合肥本地、10–30 人、1–3 店、在施 3–15 个项目的成长型装企；企业负责人深度参与回款与成本判断（`DEC-001`）。

### 场景一：负责人周一早上盘点在施盘子

- **使用人**：企业负责人。
- **触发事件**：周会前想确认「这周公司到底压着多少工程」。
- **当前动作**：打开小程序底部「项目」Tab。
- **系统下一步**：先看到四张经营指标卡（在建项目 / 在建合同额 / 回款率 / 风险项目），再按状态分段查看待开工、施工中、停工、待验收的具体项目。
- **异常处理**：任一板块数据不可确认时显示「暂不可确认」并给重试，**不得用 0 冒充事实**。

### 场景二：负责人发现某工地要拖期，需要今天定动作

- **使用人**：企业负责人。
- **触发事件**：项目经理反馈某工地材料没到，可能超过计划完工日。
- **当前动作**：在项目 Tab 按「风险优先」排序，找到该工地。
- **系统下一步**：卡片直接给出风险等级、风险原因（如「已超过计划完工日期且尚未完工」）、责任人、逾期天数和建议下一步（如「核实停工原因，明确复工责任和日期」），点击进入项目详情处理。
- **异常处理**：无风险项目不显示风险条，不制造伪预警。

### 场景三：负责人兼财务，检查回款最慢的项目

- **使用人**：企业负责人（兼财务）。
- **触发事件**：月底对账，想知道哪些工程款收得最慢。
- **当前动作**：切换到「按回款最慢」排序，查看回款率最低的项目。
- **系统下一步**：卡片显示应收合计、已收金额、回款率进度条和是否存在逾期应收；点击可下钻到该项目的收款记录。
- **异常处理**：存在逾期应收时指标卡与项目卡同时提示，逾期笔数与首页预警口径一致。

## 3. 设计原则

1. **先结论后明细**：首屏给指标与状态分布，明细往下滚。
2. **口径唯一**：风险等级与原因复用 `BusinessAlertContext`；成本完整性与毛利复用 `ProjectCostContext`；应收与回款复用 `Receivable`。前端不重算、不猜测。
3. **不完整就说不知道**：成本不完整 → 毛利为空并显示「成本未完整」；接口失败 → 显示「暂不可确认」并保留重试。
4. **风险显性、正常安静**：只有真正命中的项目才出现风险条和风险配色，正常项目保持中性卡片。
5. **同一事实跨页一致**：项目 Tab 的项目状态、金额、经理、风险必须与首页风险项目、合同履约档案、财务项目页一致。

## 5. 四张经营指标卡

| key | 名称 | 主数据 | valueType | 状态规则 | subText |
| --- | --- | --- | --- | --- | --- |
| `activeProject` | 在建项目 | 在建项目数（待开工+施工中+停工+待验收） | count | 停工数 > 0 → `danger`；否则 `normal` | 待开工 X · 施工中 Y |
| `activeContractAmount` | 在建合同额 | 在建项目对应合同当前金额合计 | amount | 标 `normal`（金额本身不参与健康判定） | 全部项目合同额 ¥X |
| `receivedRate` | 回款率 | 已收合计 / 应收合计 × 100 | percent | 存在逾期应收 → `danger`；回款率 < 60% → `attention`；否则 `normal` | 已收 ¥X / 应收 ¥Y |
| `newSignedProject` | 本月新签项目 | 本月签约的项目数（合同 `signedAt` 落在本月；无合同时回退项目建档时间） | count | 标 `normal`（数量不参与健康判定） | 上月 X 个 · 本月签约额 ¥Y · 环比 Z% |

口径说明（v1.1 已按用户裁决更新）：

- **在建**：`status ∈ {Preparing, Ongoing, Suspended, Accepting}`；`Finished`、`Settled` 不计入在建。
- **合同当前金额**：优先 `ProjectContract.currentAmount`，为 0 时回退 `baselineAmount`；无合同时回退 `Project.contractAmount`。
- **应收 / 已收**：按项目维度对既有 `Receivable` 求和（`amount` / `receivedAmount`），不做二次口径定义。
- **本月新签项目**：用户已裁决（2026-09-21）第四张卡用「本月新签项目」替代「风险项目」。风险不再单独占指标卡，改为落在每张项目卡的风险条与「风险优先」排序上。
- **风险仍必须可见**：风险等级、原因和下一步仍由 `BusinessAlertContext` 投影到每张项目卡；不在指标卡上重复计数，避免与首页「需要关注的项目」重复表达同一事实。
- **毛利不可确认**：`ProjectCostContext.summarize(project).complete() == false` 时，该项目的毛利不参与统计，前端在相关卡片上显示「成本未完整」。

## 6. 双维度分段与经营排序

### 6.1 维度切换（横向分段，带计数）

用户已裁决（2026-09-21）：**要加「合同履约中 / 已完成」合同维度分段**。为避免两排胶囊同时铺开挤占首屏，采用报价详情同款「维度切换 + 胶囊」写法：

| 维度 | key | 胶囊 |
| --- | --- | --- |
| 按项目状态 | `status` | 全部 / 待开工 / 施工中 / 停工 / 待验收 / 已完工 |
| byContract 合同履约 | `contract` | 全部 / 待签约 / 履约中 / 已完成 |

计数由服务端 `statusCounts` 与 `contractCounts` 分别返回，与卡片列表使用同一份数据口径；选中态使用品牌主色浅底胶囊。

合同阶段口径（服务端投影为 `contractStage`）：

| contractStage | 名称 | 覆盖的合同状态 |
| --- | --- | --- |
| `pending` | 待签约 | 无合同，或 `Draft`、`PendingSign` |
| `active` | 履约中 | `Signed`、`Effective`、`Active`、`Changing`、`Changed` |
| `completed` | 已完成 | `Completed`、`Settled`、`Closed`、`Terminated` |

> 「待签约」是为保证分段计数与「全部」自洽而保留的分组（无生效合同的项目不能凭空消失）；「已完成」合并了已完工/已结算/已关闭/已终止四种已结束履约的合同状态。

### 6.2 经营排序（仅负责人可见）

风险不再单独占指标卡，因此「风险优先」保持默认排序，确保负责人第一眼看到的仍是需要介入的项目：

| key | 名称 | 含义 |
| --- | --- | --- |
| `risk` | 风险优先 | 默认；高危 → 中危 → 低危 → 正常，同级按逾期天数倒序 |
| `amount` | 金额最高 | 按合同当前金额倒序，找「大单」 |
| `received` | 回款最慢 | 按回款率升序，找欠款最多的工地 |
| `due` | 工期最紧 | 按计划完工日升序，找最快要交付的工地 |
| `newest` | 最新录入 | 按项目索引倒序 |

## 7. 项目经营卡片

分层固定，从上到下：

1. **识别行**：项目名 + 状态标签；副行 = 小区 · 面积 · 项目经理。
2. **风险条**（仅命中预警时出现）：风险图标 + 风险原因文案 + 等级标签。
3. **资金行**：合同额 · 已收 · 回款率 + 回款进度条（`q` 形，品牌主色）。
4. **交付行**：当前施工阶段 + 进度百分比 + 进度条；计划完工日期，逾期时显示「逾期 N 天」。
5. **利润行**（仅负责人可见）：用户已裁决（2026-09-21）**按实际成本口径展示** —— 实际成本 + 毛利 + 毛利率；成本不完整时只显示「成本未完整 · 补齐标准成本后展示可靠毛利」，不展示 0 成本或伪毛利。
6. **动作行**：下一步建议 + 「进入处理」，点击进入项目详情。
7. **滚动居中高亮**：列表滚动时，视口垂直居中附近的那张项目卡获得**品牌色边框 + 品牌色阴影**，让负责人在长列表里始终知道「当前看的是哪一单」。高亮锚点必须绑定**当前查询维度实际渲染的列表** —— 维度切换（项目状态 / 合同履约）、分段筛选、经营排序、下拉刷新和分页追加后都要重新测量，禁止高亮停留在已消失的卡片上；卡片处于风险态时，风险信息由风险条继续承载，居中时品牌色优先。

字段与角色可见性：

| 字段 | BOSS | 其他角色 |
| --- | --- | --- |
| 合同额 / 已收 / 回款率 | 可见 | 项目经理可见合同额；客户仅看自己工地 |
| 实际成本 / 毛利 / 成本完整性 | 可见（成本不完整显示「成本未完整」） | **不可见**（服务端按角色过滤） |
| 风险等级 / 风险原因 / 下一步 | 可见 | 项目经理可见与自己项目相关的风险；其余角色不展示负责人预警文案 |
| 设计 / 项目经理 / 履约专员 | 可见 | 可见 |

## 9. 数据契约与口径

### 9.1 接口

- 路由：`project/project/overview`（Provider，继承 `Security`）。
- 入参（`AutoInject` 成员变量）：`current`、`size`、`status`（项目状态）、`contractStage`（合同履约阶段）、`keyword`、`sort`、`storeId`（预留）。
- 出参：`ProjectOverviewReport`（不做 VO 包装）。

### 9.2 响应结构

```
ProjectOverviewReport
  asOf            日期
  month           月份首日
  metrics         指标卡列表（ProjectMetricCard）
  statusCounts    项目状态计数（ProjectStatusCount）
  contractCounts  合同履约计数（ProjectStatusCount）
  projects        项目卡（Project 实体 + 只读投影字段）
  current/size/total/hasMore  分页
```

`ProjectMetricCard`：`key / label / value / valueType(count|amount|percent) / status(normal|attention|danger|unknown) / subText / trendRate`。

`ProjectStatusCount`：`key / label / count`（项目状态与合同履约两个维度复用同一结构）。

`Project` 只读投影字段（`@Transient`，与 `Customer` 客户经营投影同构）：
`riskLevel`、`riskCount`、`mainRiskType`、`riskReason`、`nextAction`、`receivedAmount`、`receivableAmount`、`actualCost`、`grossProfit`、`costComplete`、`overdueDays`、`overdueReceivableCount`、`contractStage`。

### 9.3 口径硬约束

- 不新增金额口径；所有金额来自既有合同 / 应收 / 成本对象。
- 毛利 = 合同当前金额 − `ProjectCostContext` 实际成本；`costComplete=false` 时毛利返回 `null`，前端显示「成本未完整」，**禁止用 0 成本计算伪利润**（`GAP-003`）。
- 风险等级与原因复用 `BusinessAlertContext`（逾期应收 / 停工与工期逾期 / 材料超领 / 变更率异常）。
- 排序与分页在服务端完成，前端不做二次金额排序。
- 实际成本取 `ProjectCostContext` 的 `actualCost()`；毛利 = 合同当前金额 − 实际成本。
- 合同履约阶段由合同状态投影得出（见 §6.1），不在前端按合同状态字符串自行推断。

## 10. 权限与数据范围

- Provider 必须继承 `Security`，当前员工通过 `@User` 注入；企业从登录员工取，禁止信任前端 `companyId`。
- 本接口定位为企业负责人经营聚合，使用 `TenantContext.requireBoss` 做角色校验；非负责人调用服务端直接拒绝。
- 项目集合必须按登录员工数据范围过滤（企业 / 门店 / 团队 / 本人参与），与 `project/project/page` 的访问规则一致，禁止「返回全公司再前端过滤」。
- 成本与毛利字段仅负责人可读；`@Properties` 白名单只暴露当前页面字段，不返回完整归属树。
- 跨企业、跨门店、伪造 `storeId` 必须返回无权限或空集，不得返回他企业数据。

## 11. 异常态与空态

| 场景 | 展示 | 禁止 |

| 无权限 | 服务端拒绝 | 前端隐藏代替权限 |
| 跨页跳转 | 必须携带 `projectId`，由服务端校验 | 找不到 ID 取第一条 |
