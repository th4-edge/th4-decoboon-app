# 装得清 · 企业负责人「增减项工作台」产品设计

> 批次 ID：`REQ-20260922-BOSS-CONTRACT-CHANGE-WORKBENCH`
> 模式：`feature_iteration`
> 状态：**设计与范围冻结（v1.0，2026-09-22）**，进入 development 实现
> 目标角色：企业负责人（BOSS）；店长/团队负责人/财务按数据范围与权限复用
> 端：微信小程序（现场/移动审批）；Web 批量录入沿用既有 `ContractChangeCreateView`
> 依据（业务事实源）：`SCN-004`、`DEC-001` 决策三、`MET-002`、`SOL-002`、`BR-002`、`BR-003`、`GAP-003`、`GAP-005`
> 依据（既有设计与代码）：`2026-09-21-合同增减项业务流程与交互设计.md`（v1.2 冻结）、`ContractChange`/`ContractChangeItem`、`ProjectContractContext`、`ContractChangeFulfillmentContext`、`ProjectCostContext`、`ProjectAccessContext`

## 0. 结论摘要

增减项不是"改个数字"，而是把工地现场的口头约定，变成**有发起、有审批、有客户签认、有材料下单、有合同金额与应收重算、可追溯**的正式经营事实（`SCN-004`）。

现有系统已经具备强后端能力：发起（逐条/批量）→ 审批 → 客户确认 → 同事务更新合同金额、项目合同额、应收、施工任务、材料计划、成本重算。**缺的是企业负责人视角的"一张桌子"**：

- 负责人现在只能在单项目合同页里逐个项目翻，无法一屏回答"全公司有几单要批、多少钱在途、客户确认后钱和材料有没有真的落地、改完这单还赚不赚"。
- 现有 `project/pages/change.vue` 是**项目内工作台**（3 个汇总数字 + 平铺列表），服务项目经理现场使用，不承担企业级经营视角。
- 因此新增**企业负责人增减项工作台**（企业级只读聚合 + 复用既有审批/确认动作），不改状态机、不改金额口径、不新增第二套业务规则。

一句话定位：

> **把在途变更、客户已确认、材料下单、合同金额与毛利投影放到同一屏，让负责人只做三件事：批、催、看结果。**

## 1. 真实场景（强制：至少 2 个）

### 场景一：老板午休 3 分钟审批两单变更，判断该不该批

- 使用人：企业负责人王总（BOSS，Company 数据范围）。
- 触发事件：上午两个在施项目各提交了 1 张变更单（一个主材升级 + 一个背景墙减项）。
- 当前动作：打开 App「项目 → 增减项工作台」，默认落在「待审批」。顶部固定经营指标：待审批 2 单 / 在途金额 ¥X；异常条显示"1 单待审批超 48 小时"。
- 系统下一步：按项目分组展示两单，卡片直接给变更号、项目/客户、类型、金额（+/-）、成本变化（无成本权限不返回）、发起人、等待时长；点入详情看变更前→本次→变更后、明细、签证照片、原因，填写审批意见后点「审批通过」。
- 异常处理：接口失败时整块显示「增减项状态暂不可确认」+ 重试，不显示 0 或旧值；变更后合同额会小于 0 时禁用通过并由服务端再次拒绝。

### 场景二：负责人月度复盘，发现"客户已确认但材料没下单/变更款没收"

- 使用人：企业负责人王总。
- 触发事件：月末核对在施项目经营，担心变更金额已计入合同，但材料员没下单、财务没收到变更款、成本没补齐。
- 当前动作：打开工作台切到「已确认」，异常条显示：材料未下单 X 项、变更款应收未收 ¥Y、成本未完整 Z 单；按项目分组逐项下钻。
- 系统下一步：系统展示每单"客户确认时间 / 材料已下单 vs 未下单 / 变更款应收-已收-未收 / 变更成本 / 变更后合同额与预计毛利（成本完整才显示）"，并提供「跟进材料下单」「查看项目财务」入口。
- 异常处理：任一应计成本缺失（`ProjectCostContext.complete()==false` 或无报价基线）时 `projectedGrossProfit/projectedGrossMargin=null`，App 统一显示「成本未完整」，禁止用 0 成本制造伪利润（`MET-002`/`GAP-003`）。

### 场景三（复用验证）：店长只看本门店，越权拿不到别店数据

- 使用人：门店店长（StoreManager，Store 数据范围，成本可见）。
- 触发事件：同时管理本店与邻店项目时，只想看本店变更。
- 系统下一步：同一 Provider 按 `ProjectAccessContext.visibleChild` 自动收敛到本店；跨店/跨企业项目不出现在分组、列表和汇总里。
- 异常处理：直接伪造 `projectId` 查询越权项目返回空/无权限，不泄露对象存在性。

## 2. R1–R3 迭代结论

### R1 因果

- 业务问题：负责人看不到"在途变更 + 已确认变更履约落地"的全公司盘子，审批靠通知、复盘靠翻页，变更款与材料下单容易脱节。
- 当前损失：审批超时、客户确认后材料未下单、变更款漏收、成本未补齐导致利润失真。
- 目标结果：一屏给出在途金额、待审批/待确认、客户已确认后的材料下单与应收落地、变更后合同额与预计毛利投影。
- 主对象与归属：`ContractChange` 继承项目 `company/store/team/owner`；经营归属不被项目参与关系覆盖（`SCN-004`）。

### R2 条件

- 角色：BOSS（Company）/ StoreManager（Store）/ TeamLeader（Team）/ Finance 可进入经营工作台；成本只对 Boss/StoreManager/Finance 返回（`CatalogCostContext`）。
- 状态：`Pending → Approved → CustomerConfirmed`（终态）；`Rejected/Cancelled` 保留可见、不可再流转。
- 权限：Provider 继承 `Security`，自定义详情/集合查询使用 `ProjectAccessContext.visibleChild` 在同一查询内追加数据范围，禁止先 `findById` 再判断。
- 金额：变更金额只读 `ContractChange.amount`；合同当前额只读 `ProjectContract.currentAmount`；在途投影 = 当前合同额 + Pending/Approved 金额；客户确认后金额已包含在当前合同额，不重复累加。
- 成本/利润：变更成本 = `Σ(ContractChange.costDelta)`（`MET-002`）；变更后预计成本 = `ProjectCostContext.estimatedCost(project)` + 在途及已确认变更成本（Pending/Approved/CustomerConfirmed 的 `costDelta`）；成本不完整时利润/毛利率返回 `null`。
- 履约落地：客户确认后材料计划状态 `Planned/Requested/Approved` = 未下单；`Ordered/PartiallyArrived/Arrived` = 已下单/到场；`Closed` 不计入待下单。
- 应收：客户确认后正数变更生成 `Receivable`（`stageName=合同变更`，到期 +7 天）；减项冲减未收应收余额；工作台只读汇总，不新增收款规则。
- 异常/幂等/历史：审批/客户确认继续走既有 Provider 的事务与幂等规则；工作台只读、可重复刷新，不产生副作用。

### R3 体验

- 负责人打开即见：4 个经营指标 → 异常/风险条 → 项目分组 → 变更单卡片 → 详情动作。
- 排序默认"风险优先"：待审批超时 > 待客户确认超时 > 材料未下单 > 变更款逾期 > 其他。
- 状态用文字（待审批/待客户确认/客户已确认/已驳回/已取消），颜色只做强调。
- 金额永远成组：当前合同额 → 本次变更 → 全部在途确认后预计合同额；绝不让用户自己减。
- App 只做现场快捷：审批、查看、催办入口；批量录入仍回 Web。

```text
项目 Tab（企业负责人视角）
  └─ 经营入口：增减项工作台
        ├─ 固定经营指标（4 张）
```

## 5. 经营指标与异常口径

| 指标 | 口径 | 缺省/异常 |
|---|---|---|
| 待审批 | `status=Pending` 的单数与金额 | 无数据显示 0 单，不显示金额 0 冒充 |
| 待客户确认 | `status=Approved` 的单数与金额 | 同上 |
| 本月已确认净变更 | `status=CustomerConfirmed` 且 `customerConfirmedAt` 在本月，金额可正可负 | 无数据显示「本月暂无确认」 |
| 待下单主材 | 已确认变更中 `itemType=Material` 且材料计划状态 ∈ {Planned,Requested,Approved} 或未生成计划 | 不计 Closed；已下单/到场另列 |
| 审批超 48h | Pending 且 `createTime` 早于当前-48h | 无异常不显示 |
| 确认超 72h | Approved 且 `approvedAt` 早于当前-72h | 无异常不显示 |
| 变更款应收 | 项目应收中 `stageName=合同变更`：应收/已收/未收/逾期 | 未生成应收显示「尚未生成」，不显示伪 0 结论 |
| 变更后合同额投影 | `ProjectContract.currentAmount` + 该项目 Pending/Approved 金额 | 无合同显示「无生效合同」 |
| 变更后预计毛利 | (`currentAmount + 在途`) − (`estimatedCost` + 在途及已确认变更成本)；`costComplete=false` → `null` | 显示「成本未完整」，禁止 0 成本利润 |
| 风险等级 | `high`：审批超48h/确认超72h/变更款逾期；`medium`：材料未下单/成本未完整；`low`：其余 | App 用文字标签，不用颜色代替状态 |

## 6. 变更单卡片与下一动作

卡片必须同屏给出：变更号 + 状态文字 + 类型；项目/客户；当前合同额 → 本次变更 → 全部在途确认后预计合同额；成本变化（仅成本可见角色）；发起人/审批人/等待时长；材料待下单数；风险原因与下一步。

| 状态 | 主下一步（按角色） |
|---|---|
| Pending | BOSS/财务/店长：审批通过或驳回；其他角色：等待审批 |
| Approved | BOSS/项目经理/设计师：登记客户确认；负责人：催客户确认 |
| CustomerConfirmed + 材料未下单 | 材料员/负责人：跟进材料下单 |
| CustomerConfirmed + 变更款逾期 | 财务/负责人：跟进变更款 |
| CustomerConfirmed + 成本未完整 | 财务/负责人：补齐成本 |
| CustomerConfirmed + 正常 | 查看项目财务/合同档案 |
| Rejected / Cancelled | 查看处理记录；需要再改则新建反向变更单 |

## 7. 数据契约（App ⇄ Provider）

Provider：`statistic/boss/contract-change/report`（继承 `Security`，统计域语义化 Query，禁止 DTO 命名）。

请求 `BossContractChangeQuery`：

| 字段 | 说明 |
|---|---|
| `view` | `all / pending / approved / confirmed / closed`，默认 `all` |
| `keyword` | 变更号/项目名/客户名/小区模糊搜索（服务端过滤） |
| `projectId` | 可选，单项目下钻 |
| `ownerId` | 可选，按经营负责人过滤 |
| `dimension` | `risk / project`，默认 `risk` 排序 |

响应 `BossContractChangeReport`：

- 汇总：`itemCount / pendingCount / pendingAmount / approvedCount / approvedAmount / confirmedCount / confirmedNetAmount / thisMonthConfirmedCount / thisMonthConfirmedAmount / confirmedCostDelta / projectedContractAmount / projectedGrossProfit / projectedGrossMargin / costVisible`
- 异常：`overdueApprovalCount / overdueConfirmCount / materialPendingCount / materialOrderedCount / costIncompleteCount / receivableOverdueCount / receivableOutstandingTotal`
- 期间：`periods[]`（today/yesterday/last7Days/month：createdCount、confirmedCount、confirmedAmount）
- 分组：`groups[]`（projectId/no/name、客户、合同当前额、在途金额、已确认净变更、成本变化、材料待下单、风险、项目预计毛利、currentAmount→projectedContractAmount、items[]）
- 明细：`items[]`（changeId/no/status/type、项目/客户、合同当前额与预计额、本次金额、成本变化、预计毛利、明细项计数、材料已/待下单、发起人/审批人、时间、等待时长、风险原因、下一步）

序列化：`@Properties/@AllowProperties` 白名单；无成本权限角色服务端把 `costDelta/costChange/confirmedCostDelta/projectedGrossProfit/projectedGrossMargin` 置空（`non_null` 序列化下不出现）。

## 8. 不可违反的边界

1. 不新增/修改变更状态机与审批链（`SCN-004`、2026-09-21 设计 §12）。
2. 不新增第二套金额/成本/利润口径；只读既有实体与 `ProjectCostContext`。
3. 不把"变更后预计毛利"表述为最终财务利润或现金流；它是读时投影。
4. 成本不完整时利润为空，不用 0 成本伪造。
5. 工作台不代替 `change-detail` 的审批/确认动作，不绕过服务端权限。
6. 项目内 `change.vue` 现场工作台保留，不做破坏性替换。

## 9. 验收标准（交 acceptance）

**正向**

1. BOSS 打开工作台，4 个指标、日期窗口、项目分组、变更单列表与真实变更单一致。
2. Pending 单可在工作台链路进入详情并由 BOSS 审批；审批后指标从待审批移至待客户确认。
3. Approved 单由 BOSS 登记客户确认后，合同当前额、变更款应收、材料计划、成本投影同事务更新；工作台刷新后指标一致。
4. 材料已确认变更在 `Ordered` 前计入待下单，`Ordered` 后移出。
5. 成本完整时显示变更后预计毛利；指标=合同投影−（预计成本+在途及已确认变更成本）。

**反向/边界**

6. 非经营角色调用返回 403；TeamLeader/设计师/业务员响应中不出现成本字段。
7. 跨企业/跨门店/跨团队访问变更单与汇总不可见（同一查询内数据范围）。
8. 变更后合同额 < 0 被拒绝；重复客户确认不重复生成应收/任务/材料。
9. 成本不完整、无合同、无应收计划分别为「成本未完整」「无生效合同」「尚未生成应收」，不显示 0 结论。
10. 已确认变更不可再编辑/撤回；Rejected/Cancelled 仍可在记录中查到。

**可完成状态投影**

11. 初次进入、审批成功、客户确认成功、接口异常、可选步骤完成、必做未完成、撤回/回退、重复进入八种情况均有明确状态与恢复路径。

## 10. 分期

| 期次 | 内容 | 状态 |
|---|---|---|
| P0 | 企业负责人工作台：只读聚合 + 项目分组 + 异常/风险 + 日期窗口 + 复用审批/确认入口 | 本次实现 |
| P1 | 变更后动态毛利写回 `ProjectCostContext`（把已确认变更成本纳入统一聚合）、变更单详情履约结果聚合 | 依赖 `GAP-5`、`GAP-3` |
| P2 | Web 批量工作台与 App 打通、客户拒绝反向变更单的向导化 | 依赖后续评审 |
