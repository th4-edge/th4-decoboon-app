# 员工工资与提成发放 App 改造评估

> 文档编号：APP-IMPACT-20261007-01  
> 版本：v0.1  
> 状态：评估稿  
> 依据：`DEC-017`、`BR-015`、`ANS-BIZ-20261006-002`、后端 P0 规格  
> 目标：评估员工工资、月度考勤、提成计提/自动释放、工资单、员工发放和工资条进入 App 后，对现有功能体系、页面、路由和权限的改造范围。

---

## 0. 结论

这不是在“工人工资”付款页上加一个员工选项，而是新增一条 **员工薪酬业务链**。

当前 App 的财务体系是：

```text
项目/合同 -> 应收/应付 -> 收付款 -> 资金台账 -> 凭证
```

其中 `salary` 只代表工人工资，服务于工人档案和工资发放凭证。员工工资与提成需要新增：

```text
薪酬方案 -> 月度考勤 -> 工资单
合同签约 -> 提成计提 -> 回款比例自动释放
工资单/提成 -> 员工工资应付 -> 员工发放 -> 资金台账 -> 工资条
```

因此建议：

- 新增 `subpackages/payroll` 员工薪酬分包；
- 新增 `domains/payroll` 领域模型和 API；
- 财务首页增加“员工薪酬”入口组；
- “我的”页面增加“我的已发放工资条/我的提成/我的考勤”；
- 现有工人工资页面保持原语义，不把员工工资塞进 `payables?type=salary`；
- 项目账本、付款记录、资金台账补充员工工资/提成展示和成本口径；
- 不新增主 Tab，优先复用财务 Tab 和“我的”页面。

## 1. 当前 App 现状

### 1.1 当前财务能力

已有页面：

- `pages/finance/index.vue`：财务工作台；
- `subpackages/finance/pages/payables.vue`：应付账款/工人工资；
- `subpackages/finance/pages/payments.vue`：付款记录；
- `subpackages/finance/pages/entry.vue`：应收、收款、应付、付款、手工记账；
- `subpackages/finance/pages/projects.vue` / `project.vue`：项目账本与项目财务；
- `subpackages/finance/pages/ledger.vue`：资金台账；
- `subpackages/finance/pages/vouchers.vue`：收付款凭证；
- `subpackages/labor/pages/workers.vue` / `worker-edit.vue`：工人档案。

### 1.2 当前语义限制

- `PayableType.salary` 当前代表“工人工资/班组劳务”，不能承载员工工资；
- `Payment` 当前有 `worker` 关联，但没有 `employee` 关联；
- App 当前没有员工薪酬方案、月度考勤、工资单、工资条、提成明细等模型；
- 当前“员工绩效业绩”页面是统计视图，不是提成计算和发放依据；
- 当前“工人工资”应付、工资凭证、工人档案链路不能被员工工资链路复用。

## 5. 角色路径改造

### BOSS

```text
财务 Tab -> 员工薪酬
-> 查看本月考勤/工资单
-> 确认工资单
-> 查看发放结果和项目/企业成本
```

### 财务

```text
财务 Tab -> 员工薪酬
-> 维护薪酬方案
-> 处理月度考勤
-> 生成工资单
-> 提交 BOSS 确认
-> 发起员工工资/提成发放
-> 核对资金台账
```

### 店长

```text
首页/我的 -> 本店薪酬
-> 确认本店月度考勤
-> 查看本店员工个人工资构成
```

### 员工本人

```text
我的 -> 我的工资条 / 我的提成 / 我的考勤
```

### 工人/班组

```text
财务 -> 工人工资 -> 工人付款凭证
```

员工薪酬和工人工资必须保持两条独立路径。

## 6. 导航与信息架构

建议不新增主 Tab，原因：

- BOSS/财务已有“财务”Tab；
- 店长和普通员工没有财务 Tab；
- 员工工资条属于个人低频查看，更适合“我的”；
- 员工薪酬管理属于财务工作台能力，不需要抢占全局 Tab。

建议层级：

```text
财务 Tab
  -> 资金收付
  -> 往来管理
  -> 员工薪酬（新增）
  -> 账务核算

我的
  -> 我的工资条（新增）
  -> 我的提成（新增）
  -> 我的考勤（新增）
  -> 员工薪酬管理（仅 BOSS/财务）
```

店长入口建议放在首页快捷入口或“我的”业务组，显示“本店薪酬”，不显示全公司工资。

## 8. 财务页面联动

### 应付

员工工资和提成形成员工工资应付，但：

- 不复用 `PayableType.salary`；
- 不和工人工资合并统计；
- 项目归属进入项目成本，企业归属进入企业费用；
- 一项只能有一个归属。

### 付款

员工发放：

- 核销员工工资/提成应付；
- 写同一 `Ledger`；
- `Payment.employee` 关联员工；
- 失败重试不重复写流水；
- 不与工人工资凭证补录流程混用。

### 项目账本

项目成本应展示：

- 材料成本；
- 工人/班组人工成本；
- 项目归属员工工资；
- 项目归属员工提成；
- 成本不完整时继续显示“成本未完整”。

### 资金台账

员工工资/提成发放作为普通支出流水进入同一资金台账，但来源显示为员工工资或员工提成，不伪装成供应商付款或手工记账。

## 9. 后端依赖与 App 开发顺序

App 不能先于后端独立完成。建议顺序：

1. 冻结 App 页面字段、角色路径和状态展示；
2. 后端完成员工工资语义、员工付款关联、工资单、提成、自动释放和权限；
3. App 先接薪酬工作台、工资单、工资条、提成、考勤；
4. 再接员工发放和资金台账；
5. 最后补通知、审计和体验优化。

若后端未先提供稳定契约，App 不应自行用本地状态模拟工资单或提成状态。

## 11. 风险与不做什么

风险：

- 把员工工资混入现有 `salary` 应付，导致工人工资和员工工资重复或串账；
- 用绩效数据直接算提成，绕开合同、回款和计提规则；
- 前端用本地布尔表达工资单完成，破坏可完成状态投影；
- 店长跨店看到工资数据；
- 工资发放重复写资金流水；
- 项目成本和企业费用重复归集；
- 提成自动释放后发生退款，直接反改历史。

明确不做：

- 不新增主 Tab；
- 不改变工人档案和工人工资凭证链路；
- 不把员工工资进入完整 HR 或法定会计；
- 不在 P0 做自动多人分摊、复杂提成阶梯和银行直连；
- 不用前端页面隐藏代替服务端工资权限。


> 补充冻结（EV-069）：工资条必须等到实际发放完成后才对本人员工可见；确认但未发放时员工端不展示。
