# 财务工作台快捷入口信息架构

> 日期：2026-10-05  
> 范围：App 财务工作台一级快捷入口、分组顺序、角色只读状态与验收规则。

## 1. 业务问题

旧版财务快捷入口把“查看计划、登记动作、项目核算、供应商往来、手工记账”混在一个扁平宫格里。用户需要先理解功能名称，再自己判断今天应该先做什么，不符合财务按资金事实推进工作的习惯。

## 2. 场景闭环

### 场景一：财务每天开始登记收付款

- 使用人：财务 / 企业负责人。
- 触发事件：客户回款到账，或需要安排供应商、工人、项目款付款。
- 当前动作：进入财务工作台，先登记真实收付款。
- 系统下一步：自动核销应收或应付，并写入资金台账和项目账本。
- 异常处理：非财务编辑角色只能查看，点击登记动作提示“当前账号仅可查看财务数据”。

### 场景二：负责人处理逾期应收和待付风险

- 使用人：企业负责人。
- 触发事件：发现逾期应收或供应商催款。
- 当前动作：查看应收计划、应付账款、工人工资和供应商往来。
- 系统下一步：进入对应明细或项目账本，核实计划、责任人和资金缺口。
- 异常处理：应收应付数据不完整时不展示伪汇总，按后端事实状态显示。

## 3. 业务主导排序

快捷入口不再按页面代码顺序排列，而按财务真实工作顺序分成三组：

### 3.1 资金收付

1. 登记收款
2. 登记付款
3. 手工记账

设计理由：先记录真实发生的资金事实。收款核销应收，付款核销应付，手工记账只处理自动核销覆盖不到的场景。

### 3.2 往来管理

1. 应收计划
2. 应付账款
3. 工人工资
4. 供应商往来

设计理由：资金事实登记后，再管理客户、供应商和工人的待收待付计划。先看收入侧，再看支出侧，工资和供应商归入应付管理。

### 3.3 账务核算

1. 资金台账
2. 项目账本
3. 收付凭证

设计理由：最后进入统一核算。资金台账回答“钱怎么流动”，项目账本回答“项目赚不赚钱”，收付凭证回答“单据如何归档和套打”。

## 4. 交互规则

- 每个分组必须有业务说明，不能只显示功能名。
- 分组标题使用品牌渐变柱，形成明确层级。
- 登记类动作必须校验编辑权限；只读角色仍可查看列表和台账。
- 点击只读受限动作必须给出明确提示，不能静默无响应。
- 同一分组内保持业务顺序，不按使用频率或开发历史排序。
- 金额汇总仍以后端计算为准，前端只展示。

## 5. 资金台账凭证入口

旧版把「收付凭证」和「选记录出凭证」作为两个同等按钮并排在页面顶部，用户无法判断两者关系：

- 一个是查看已有凭证
- 一个是进入当前台账的选择模式

现改为统一凭证动作卡：

- 标题：收付凭证
- 说明：当前筛选 N 笔流水，可勾选生成凭证
- 次要动作：查看已有凭证
- 主要动作：选记录生成凭证

进入选择模式后：

- 页面顶部显示选择模式说明和已选笔数
- 页面底部固定显示已选合计和生成凭证按钮
- 点击流水卡片勾选/取消
- 无可用流水时禁用生成入口，不进入空白选择模式

## 6. 验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| FIN-IA-01 | 财务进入工作台 | 依次看到资金收付、往来管理、账务核算三组 |
| FIN-IA-02 | 点击登记收款 | 进入收款登记页，收款后自动核销应收并进入台账 |
| FIN-IA-03 | 负责人查看逾期应收 | 从应收计划进入明细，金额与台账、项目账本一致 |
| FIN-IA-04 | 只读角色点击登记动作 | 显示只读提示，不进入无权限页面 |
| FIN-IA-05 | 查看资金流水 | 资金台账展示后端汇总净现金流，不使用当前页记录重算 |
| FIN-IA-06 | 查看项目盈利 | 项目账本复用统一成本完整性口径，成本不完整时禁止展示伪利润 |
