# 员工工资与提成 App P0 页面与接口映射

> 文档编号：APP-CONTRACT-20261007-01  
> 状态：`iterating_for_technical_review`  
> 依据：`DEC-017`、`BR-015`、`ANS-BIZ-20261006-002`、后端 P0 规格、`EV-065`、`EV-069`  
> 目的：把员工工资与提成 P0 从业务口径转成 App 页面、路由、权限和 API 契约，作为后续开发切片。

---

## 0. 冻结范围

### 做

- 员工薪酬方案；
- 月度考勤申报和确认；
- 工资单、工资项、工资条；
- 签约计提 + 回款比例自动释放；
- 员工工资/提成应付、员工发放、资金台账；
- 项目/企业成本唯一归属；
- BOSS、财务、店长、员工本人四类角色权限。

### 不做

- 完整 HR、打卡、加班费、招聘、劳动合同和绩效；
- 个税、社保、公积金代扣代缴和申报；
- 公司经营利润和店长门店利润；
- 自动阶梯提成、自动多人分摊和银联/银行代发；
- 工人工资和员工工资混用。

## 3. 领域模型

新增 App 领域目录：


### 3.1 关键模型

```ts
CompensationScheme {
  id, employee, company, store?, effectiveFrom, effectiveTo?,
  baseSalary, status, createdBy
}

AttendanceSummary {
  id, employee, company, store, month,
  scheduledDays, normalDays, personalLeaveDays, sickLeaveDays, absenceDays,
  externalDays, annualLeaveDays, compLeaveDays,
  status, confirmedBy, confirmedAt
}

CommissionItem {
  id, employee, company, store, project, contract,
  contractAmount, manualRate, commissionAmount,
  accruedAmount, releasedAmount, paidAmount,
  releaseRecords[], status, createdBy
}

PayrollSheet {
  id, company, store?, period, status,
  attendanceComplete, commissionComplete,
  totalGrossAmount, totalDeductionAmount, totalNetAmount,
  payableGenerated, paymentStatus, confirmedBy, confirmedAt
}

PayrollItem {
  id, sheet, employee, project?,
  attribution: 'project' | 'company',
  baseSalaryAmount, attendanceDeduction, commissionAmount,
  bonusAmount, allowanceAmount, socialInsuranceAmount, taxAmount, otherDeduction,
  grossAmount, deductionAmount, netAmount,
  sourceCommissionIds[]
}

Payslip {
  id, employee, payrollSheet, period,
  grossAmount, deductionAmount, netAmount,
  items[], publishedAt
}
```

`Payment` 扩展：

```ts
Payment {
  ...,
  employee?: Employee,
  payrollSheet?: PayrollSheet,
  commissionItems?: CommissionItem[]
}
```

### 3.2 财务语义

- 员工工资应付：`EmployeeSalary`；
- 员工提成应付：`EmployeeCommission`；
- 不复用工人工资 `Salary`；
- 一个 `PayrollItem` 只能归项目或企业；
- 员工工资发放写同一 `Ledger`，不新建资金账。

## 6. 权限改造

新增 Capability：

```ts
view:payroll
edit:payroll
confirm:payroll
pay:payroll
edit:attendance
view:ownPayslip
view:commission
view:sensitive-payroll
```

建议矩阵：

| 能力 | BOSS | 财务 | 店长 | 员工本人 |
| --- | --- | --- | --- | --- |
| `view:payroll` | ✅ | ✅ | 本店 | 本人 |
| `edit:payroll` | ✅ | ✅ | ❌ | ❌ |
| `confirm:payroll` | ✅ | ❌ | ❌ | ❌ |
| `pay:payroll` | ✅ | ✅ | ❌ | ❌ |
| `edit:attendance` | ✅ | ✅ | 本店 | 本人申报 |
| `view:sensitive-payroll` | ✅ | ✅ | ❌ | ❌ |
| `view:ownPayslip` | ✅ | ✅ | ✅ | ✅ |
| `view:commission` | 全公司 | 全公司 | 本店 | 本人 |

路由守卫规则：

- 无 `view:payroll` 不能进入薪酬工作台、方案、工资单和提成管理页；
- 无 `edit:payroll` 不能编辑薪酬方案和工资单；
- 无 `confirm:payroll` 不能确认工资单；
- 无 `pay:payroll` 不能进入员工发放；
- `view:sensitive-payroll` 控制银行卡、身份证、个税明细字段；
- 店长和员工页面必须由服务端再次验证门店/本人范围。

## 8. 开发顺序

1. **后端契约冻结**：员工工资语义、员工发放关联、工资单、提成自动释放、权限和迁移编号。
2. **App 领域层**：`domains/payroll` 的 model/api/meta 和 finance 扩展。
3. **权限与路由**：capabilities、guard、config、pages.json。
4. **财务端 P0**：工作台、薪酬方案、考勤、工资单、提成、员工发放。
5. **员工端 P0**：我的工资条、提成、考勤。
6. **财务联动**：应付、付款、项目账本、资金台账。
7. **消息与审计**：动态通知和敏感字段审计。

## 9. 验收出口

- BOSS/财务能生成、确认、发放工资单；
- 店长通过本店专用页面确认考勤并查看本店员工工资构成；
- 员工只能在工资/提成实际发放成功后看到本人工资条；未发放时不可见；
- 提成按累计有效回款比例自动释放；
- 跨店、跨企业、员工越权访问被拒绝；
- 工资支付只写一次资金流水；
- 工人工资和员工工资不混算；
- 项目成本和企业费用不重复计成本。


> 补充冻结（EV-069）：工资条必须等到实际发放完成后才对本人员工可见；确认但未发放时员工端不展示。
