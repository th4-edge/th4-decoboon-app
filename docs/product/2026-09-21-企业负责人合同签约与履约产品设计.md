# 装得清小程序 · 企业负责人合同签约与履约产品设计

> 状态：待用户确认（草案 v1.0，尚未开发）
> 范围：微信小程序 BOSS 视角的「合同签约工作台 / 签约确认台 / 合同履约档案」；不含 Web 与后端实现
> 日期：2026-09-21
> 依据：`DEC-001`、`DEC-002`、`DEC-003`、`BR-002`、`BR-004`、`SCN-002`、`SCN-004`、`SCN-006`、`MET-002`、`GAP-003`、`GAP-005`、`CAP-001`

## 0. 结论摘要

把「合同」从小程序里的一张基本信息卡，升级为**企业负责人的单份合同经营档案**：一份合同页同时回答「钱、货、工、变、选」五件事。

- **钱**：签了多少、约定怎么收、已经收了多少、还欠多少、逾期没有。
- **货**：成本多少、成本是否完整、利润和毛利率是否可信。
- **工**：工地到哪一步、计划何时完工、有没有验收卡住。
- **变**：改了多少、还有几单没处理、客户确认没有。
- **选**：主材选材确认了没有、确认人是谁。

页面结构统一采用 **Hero 结论卡 + 分区板块 + 底部动作条**，与 `quote/pages/detail.vue`（报价谈单）和 `design/pages/scheme.vue`（设计方案）保持同一套「先结论、再下钻」的运营视角写法。

> 重要边界：主材选材（文本化）与合同行快照两个能力**当前后端不存在**，本设计给出页面方案与数据契约，标注为「待实现」，不得在开发完成前作为可用能力对外表达。

## 1. 为什么要改

### 1.1 现状（2026-09-21 代码事实）

| 环节 | 当前位置 | 现状 |
| --- | --- | --- |
| 签约入口 | `subpackages/project/pages/sign-workbench.vue` | 报价已确认客户的**列表**，只有待签约/已签约筛选、待签约总金额、停留天数流失风险 |
| 签约动作 | `subpackages/project/pages/create.vue` | 一个**三步表单**：选报价 → 录最终价/日期/选付款与施工计划 → 生成合同 → 生效生成项目 |
| 施工计划模板 | `subpackages/plan/**` | 已有企业模板编辑与目录 |
| 合同信息 | `subpackages/project/pages/detail.vue` | 已签约后，合同摘要与资金进度被**拆散塞进工地页**，只对业主展示摘要卡 |
| 报价 | `subpackages/quote/pages/detail.vue` | 已做运营化改版：Hero + 版本切换 + 收款 + 变更 + 明细分组 + 底部动作条 |
| 收款 | `subpackages/finance/pages/receivables.vue` | 独立财务页，与合同页面**没有互相引用** |
| 增减项 | `subpackages/quote/pages/detail.vue`、`project/ContractChangeCreateView`(Web) | 变更在报价页里，合同页看不到 |
| 选材 | 不存在 | 后端、前端均无实现（`CAP-001` 标注「待建设」） |

### 1.2 问题（老板视角）

1. **签约前看不到「该不该签」的判断依据**：签约页只让选报价、填价格，看不到这单预计成本、预计毛利、报价里有哪些风险报价项。
2. **签约后看不到「这一单赚不赚钱」**：合同金额、已收、未收、成本、利润分散在 4 个页面，且财务页存在 `GAP-003` 记录的成本口径冲突风险。
3. **合同和工地是断开的**：老板想知道「合同签了，工地干到哪了」，必须自己在项目列表里找。
4. **变更是黑盒**：合同变更后金额变了，但合同页不体现「原始报价额 vs 当前金额」的差异来源。
5. **选材没有落点**：`DEC-003` 已确认选材以文本保存，但小程序没有任何入口，设计师和客户确认的东西无处沉淀。

### 1.3 目标

在**不新增业务裁决、不改变状态机、不改变金额口径**的前提下：

- 让企业负责人在**一个页面**完成对单份合同的经营判断。
- 让签约动作从「填表单」变成「看结论 → 确认 → 生效」。
- 让合同、报价、收款、成本、变更、工地、选材**共享同一套对象 ID 上下文**，跨页跳转必须携带并校验 ID（`DEC-002` 硬性边界）。

## 2. 真实业务场景

默认样本：合肥本地、10–30 人、1–3 店、在施 3–15 个项目的成长型装企；老板深度参与报价、成本和回款（`DEC-001` 决策三）。

### 场景一：客户刚确认报价，老板当天要决定怎么签

- **使用人**：企业负责人。
- **触发事件**：设计师通知「XX 小区王总报价已确认，明天上午签合同」。
- **当前动作**：老板打开签约工作台，找到这条待签约记录。
- **系统下一步**：进入**签约确认台**，先看到客户/房屋、报价金额、设计师、设计方案入口、报价里的材料与成本范围；再录入最终签约价、签约日期、开工与完工日期，选择付款计划和施工计划，最后确认生效并生成唯一项目。
- **异常处理**：没有已确认报价时不允许进入签约；报价成本不完整时显示「成本未完整」且不展示预计毛利；重复确认生效必须返回原项目而不是新建。

### 场景二：老板早晨巡检在履约合同，判断该催谁的钱

- **使用人**：企业负责人。
- **触发事件**：月初，需要安排本月回款。
- **当前动作**：在签约工作台切到「履约中」，逐份打开合同档案。
- **系统下一步**：合同档案第一屏给出「合同金额 / 已收 / 未收 / 逾期」四段结论，付款计划列出每个节点的比例、金额、触发条件、到期日、到账状态；点节点可进入应收详情登记收款。
- **异常处理**：财务接口失败时整块显示「回款状态暂不可确认」，保留重试入口，不得沿用旧值或显示 0。

### 场景三：开工后客户要加做背景墙，老板拍板审批

- **使用人**：企业负责人（审批）、项目经理（发起）。
- **触发事件**：客户现场提出增项。
- **当前动作**：老板打开对应合同档案的「变更」板块。
- **系统下一步**：看到待处理变更单数量与金额影响；进入变更详情审批；审批通过后由客户确认，确认后只更新「当前合同金额 / 应收 / 材料 / 任务 / 成本」，**原始签约额与合同行快照不变**（`SCN-004`）。
- **异常处理**：变更未审批不能被客户确认；重复确认不重复生成应收；已采购/已施工的事实只能补偿，不能删除。

### 场景四：客户问「我家的主材到底定了没」

- **使用人**：企业负责人。
- **触发事件**：客户在群里问选材进度。
- **当前动作**：老板打开该合同档案的「选材」板块。
- **系统下一步**：显示最新选材文本版本、确认人、确认时间、正文摘要；可复制发给客户。
- **异常处理**：尚未登记选材时显示「未登记」并给出设计师处理入口；该板块**只读展示文本，不改变报价、合同、成本、材料计划和采购数据**（`BR-004`）。

## 3. 设计原则

### 3.1 运营视角（对齐报价谈单与设计方案）

参考 `quote/pages/detail.vue` 与 `design/pages/scheme.vue` 已验证的做法：

1. **Hero 先给结论**：单号、状态、核心金额一屏可见。
2. **金额三段式**：合同金额 → 已收 → 未收，永远放一起，不给用户做减法。
3. **分区可下钻**：每个板块是一个「结论 + 明细摘要 + 进入专业页」的三件套。
4. **状态用文字不用颜色解释**：颜色只是强调，含义必须写出来。
5. **底部动作条统一**：主操作常驻底部，随状态变化，其余动作收进动作区。
6. **明细双视图**：合同范围按「按区域 / 按类型」切换（沿用报价页已实现的视图切换）。

### 3.2 老板视角的三个「不要」

- 不要用 0 冒充成本：`costComplete=false` 时利润与毛利率返回 `null`，显示「成本未完整」（`MET-002`、`GAP-003`）。
- 不要隐藏终态：`Terminated`、`Closed` 等状态必须明确展示，不能消失（`DEC-002`）。
- 不要猜下一步：规则未命中时显示「待业务确认」并禁用主操作，前端不推进状态。

## 5. 页面设计

### 5.1 合同签约工作台（改造 `sign-workbench.vue`）

由「报价待签约列表」升级为「签约漏斗 + 合同档案入口」。

**顶部经营条**（保留并扩展现有 3 段）

| 指标 | 口径 | 来源 |
| --- | --- | --- |
| 待签约 | 报价 `Accepted` 且未生成合同 | 现有 |
| 待签约金额 | 待签约报价金额合计 | 现有 |
| 履约中 | 合同 `Effective/Active/Changing/Changed` | 新增 |
| 待回款金额 | 履约中合同「应收总额 − 已收」合计 | 新增 |

**筛选**：全部 / 待签约 / 履约中 / 已完成。

- 待签约卡：沿用现有字段（客户、电话、房屋、面积、报价额、设计师、停留天数、流失风险）。
- 履约中 / 已完成卡：合同号、客户、房屋、**当前合同金额**、已收/未收、项目名与工地进度、变更待办数。

**主操作**：

- 待签约 + BOSS → 「去签约」进入签约确认台。
- 履约中 → 「查看合同」进入合同履约档案。

### 5.2 签约确认台（改造 `project/create.vue`）

由三步表单升级为「签约前结论 → 填写签约信息 → 确认生效」。保留原有 3 步进度条语义，但每步都有结论卡。

**步骤 1 · 确认报价（只读结论）**

- 客户 / 房屋 / 面积。
- 报价单号、版本、金额、状态。
- 设计师。
- 入口：查看设计方案、查看报价明细（携带 `quoteId`、`propertyId`）。
- 成本结论：预计成本、毛利基线、`costComplete` 状态（不完整显示「成本未完整」）。

**步骤 2 · 合同与计划**

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| 最终签约价 | 是 | > 0，最多两位小数；生成基线后不可改 |
| 签约日期 | 是 | ≤ 今天 |
| 计划开工 | 是 | — |
| 计划完工 | 是 | ≥ 开工 |
| 付款计划 | 是 | 目录优先企业默认/已启用模板 |
| 施工计划 | 是 | 同上 |
| 付款说明 | 否 | ≤ 128 字 |

- 选定付款计划后，实时预览节点名称与比例。
- 选定施工计划后，实时预览阶段链路。

**步骤 3 · 确认生效**

- 生效后系统动作提示（原文口径，不得夸大）：「合同生效后，系统自动冻结报价与合同行快照，并生成施工阶段、任务、材料计划和应收计划。后续金额调整必须通过合同变更单完成。」
- 底部主操作按状态变化：`生成合同基线` → `确认签约` → `确认生效并生成唯一项目` → `查看已生成项目`。
- 已生效合同再次进入时，本页只读并引导到合同履约档案。

### 5.3 合同履约档案（新增 `subpackages/project/pages/contract.vue`）

**这是本次重构的核心页面。** 单份合同的经营档案，从上到下 6 个板块。

#### ① Hero 结论卡

- 合同号、状态标签（区分 `Signed` 与 `Effective`）。
- 客户名、电话、房屋地址、面积。
- **三段金额**：最终签约额 / 当前合同金额 / 未收金额。
- 签约日期、计划开工、计划完工。
- 期次：`项目 xxx`（可点进入工地）。

#### ② 金额与回款（钱）

- 结论：应收总额、已收、未收、其中逾期金额。
- 付款计划节点列表，每行：节点名、比例、金额、触发条件（含关联阶段）、到期日、状态（待收/部分/已收/逾期）。
- 节点与应收通过 `planNode` 关联，状态取应收实际状态，不使用计划比例反推。
- 入口：应收明细（携带 `contractId`）/ 登记收款（财务权限可见）。

#### ③ 成本与利润（货）

- 结论：预计成本、实际成本、是否成本完整、项目毛利、毛利率。
- `costComplete=false`：毛利与毛利率显示「成本未完整」，不显示数字、不显示 0。
- 成本来源说明：签约成本快照 / 采购到货实际成本。
- 入口：项目财务（携带 `projectId`）。
- 权限：成本字段按角色过滤，设计师、业务员、项目经理默认不可见（`BR-003`）。

#### ④ 合同范围（之前的报价）

- 说明条：「以下为签约时冻结的合同行快照，共 N 项，来源报价 XXX V1。签约后主数据变化不回写历史。」
- 视图切换：**按区域 / 按类型**（沿用报价页双视图）。
- 每组折叠，组头显示组名、项数、金额合计。
- 行内容：名称、品牌规格、单位数量、单价、金额。
- 入口：查看原始报价（携带 `quoteId`）。

#### ⑤ 变更（增减项）

- 结论：累计变更金额、待处理变更数、已确认变更数。
- 变更单列表：编号、金额变化（正负带符号与颜色）、状态、发起人、时间。
- 入口：新建变更（有权限时）/ 变更详情。
- 状态流转沿用 `pending → approved → customerConfirmed`，拒绝/取消保留展示。

#### ⑥ 工地联动

- 项目名、项目状态、整体进度条、当前阶段、阶段 `done/total`。
- 计划完工 vs 实际进展。
- 待验收数量。
- 入口：工地详情（携带 `projectId`）、施工计划。

#### ⑦ 选材（主材选材文本）

- 有记录：显示最新版本摘要（前若干字）、版本号、确认人、确认时间、「查看全文」。
- 无记录：显示「未登记选材」+ 设计师处理入口。
- 明确标注：选材文本不影响合同金额、成本与材料数量。
- **当前状态：待实现**（后端无对象，`GAP-005` 部分问题待冻结）。

#### 底部动作条（按状态）

| 合同状态 | 主操作 | 次操作 |
| --- | --- | --- |
| `Draft` / `PendingSign` | 去签约 | 修改签约信息 |
| `Signed` | 确认生效并生成项目 | 修改履约信息 |
| `Effective` / `Active` / `Changing` / `Changed` | 登记收款 | 新建变更 / 查看工地 |
| `Completed` / `Settled` | 查看结算 | 查看工地 |
| `Terminated` / `Closed` | 查看原因（只读） | — |

## 6. 状态与字段冻结（可完成状态投影）

签约确认台的三步为可完成状态投影，按 `AGENTS.md` 要求冻结 `key / label / required / source_provider / completion_predicate / count / refresh_triggers / next_action / 异常态`。

| key | label | required | source 判定 | completion_predicate | count 分母 | refresh_triggers | next_action | 异常态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `quote` | 确认报价 | 是 | 报价对象 `status ∈ {Accepted, Converted}` 且已关联本合同 | 存在客户已确认报价 | 1 | 选择报价、重新进入 | 填写签约信息 | 无已确认报价→禁签 |
| `contract` | 合同签约 | 是 | 合同存在且 `signedAmount > 0` | 合同 `status ≥ Signed` | 1 | 生成基线、提交签约 | 确认生效 | 签约失败→保留草稿 |
| `project` | 生成项目 | 是 | 项目对象存在且引用本合同 | 合同 `status ≥ Effective` 且存在 `projectId` | 1 | 合同生效 | 查看项目 | 生效失败→仍停留签约台 |

- 必做分母固定为 3；「付款说明」等可选项完成不改变分母。
- 状态必须来自服务端真实对象，禁止 `done: true/false`、演示数据或前端布尔值。
- 重复进入、下拉刷新、跨页写入后必须重新读取合同与项目状态。

## 7. 口径与边界

### 7.1 金额口径

| 字段 | 含义 | 是否随变更变化 |
| --- | --- | --- |
| `baselineAmount` | 报价基线金额 | 否 |
| `signedAmount` | 最终签约价（签约冻结） | 否 |
| `currentAmount` | 当前合同金额（含已确认变更） | 是 |
| `receivableAmount` | 应收计划总额 | 是 |
| `receivedAmount` | 已收金额 | 是 |
| `outstandingAmount` | 未收 = 应收 − 已收 | 是 |

### 7.2 成本与利润口径（`MET-002` / `GAP-003`）

- 履约档案的成本与利润**必须**经过 `ProjectCostContext` 口径，不得在页面本地用「合同金额 − 标准成本」自算。
- 任一应计成本缺失：`costComplete=false`、`grossProfit=null`、`grossMargin=null`，展示「成本未完整」。
- 区分三种毛利（预计 / 动态 / 结算），页面标题必须写明是「当前动态毛利」。

### 7.3 权限与数据范围

- 合同档案继承 `company → store → team → owner` 归属，仅可通过登录员工数据范围访问。
- 成本相关字段按角色过滤；设计师、业务员、项目经理默认不可见成本价（`BR-003`）。
- 跨页跳转必须携带对象 ID 并由服务端校验；禁止「找不到 ID 就取列表第一条」（`DEC-002`）。
- 签约与生效仅 BOSS 可执行；其他角色看到「请联系企业负责人完成合同签约」。

### 7.4 选材边界（`BR-004` / `DEC-003`）

- 选材只存文本 + 归属 + 维护人/确认人/时间 + 版本，**不拆逐材料结构化字段**。
- 选材不得反向修改报价、合同、成本、材料计划数量、采购或库存。
- 变更时保留历史确认版本，形成新版本，不无痕覆盖。

## 10. 验收标准（供 acceptance lane 设计用例）

**正向**

1. 报价已确认 → 签约确认台三步全部 `done` → 合同 `Effective` → 唯一项目生成，金额与报价快照一致。
2. 履约中的合同档案：金额三段、付款计划节点状态、成本完整性、合同范围分组、变更列表、工地进度同时可见且互相可跳转。
3. 合同范围按区域/按类型切换结果一致，合计等于合同金额。

**反向 / 边界**

4. 未接受报价无法进入签约。
5. 未生效合同不能生成项目；重复生效不产生第二个项目。
6. 状态不合法时主操作禁用且不推进状态。
7. 非 BOSS 角色签约入口被服务端拒绝。
8. 跨企业 / 跨门店 / 跨团队访问合同档案返回无权限。
9. 成本不完整时毛利与毛利率为空并显示「成本未完整」。

**异常态**

10. 合同、财务、成本接口分别返回失败时，对应板块显示「暂不可确认」，不显示 0 或旧值。
11. 合同已签未生效、已生效无项目、无合同行快照、未登记选材各自有明确空态。

**可完成状态投影**

12. 初次进入、动作成功、接口异常、可选步骤完成、必做未完成、删除/回退、重复进入七种情况均验证三步状态。
