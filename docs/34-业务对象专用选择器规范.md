# App 业务对象专用选择器规范

> 上位依据：装得清业务智能体 `DEC-021`、`DEC-023`、`BR-019`、`BR-021`、`ANS-BIZ-20261007-004`、`ANS-BIZ-20261007-006`
> 研发门禁：先填写 `T15-业务概念选择器设计评审单`，取得 `T06/T12` 后再进入产品规划和研发。
> 原则：选择机制统一，业务模型各自表达。
> 跨端唯一执行细则：`../../../后端代码/th4-decoboon/docs/design/35-业务对象选择器与选择结果展示规范.md`

## 1. 核心原则

不构建一个包揽所有对象的统一选择器。项目、客户、房屋、账务分类、报价分项、工人、供应商、员工、应收、应付分别按数据概念和场景构建专用选择器。

统一的是：

- 选择入口、取消、清除；
- 服务端搜索、分页、权限过滤；
- 加载/空/失败/无权限/失效状态；
- 上下文联动和依赖字段失效；
- `select(value) | clear` 回传契约；
- 保存时服务端重新校验。

## 2. 对象专用模型

| 对象 | App 选择器必须表达 |
| --- | --- |
| 项目 | 状态分组、正常/接管、设计师、常用项目、客户、地址、阶段；界面不显示内部项目编号 |
| 客户 | 负责人、状态、最近跟进；有多套房屋时不得自动选第一套 |
| 房屋 | 客户归属、小区/楼栋/房号、面积、显式选择 |
| 账务分类 | 一级/二级树、方向、启用状态、完整路径 |
| 费用分类 | 名称、说明、基础/企业分类、启用状态 |
| 内容模板 | 名称、画幅、建议时长、片段范围、版本、状态 |
| 报价 | 客户、房屋、金额、确认状态、设计师；界面不显示内部报价编号 |
| 报价分项/项目库 | 分类树、品牌/系列/规格、区域、单位、价格、多选数量、启用状态 |
| 工人 | 姓名、工种、手机号、状态 |
| 供应商 | 名称、合作状态、结算方式、账期 |
| 员工 | 姓名、角色、门店、团队、状态 |
| 应收/应付 | 项目、类型、到期日、待收/未付金额、状态 |

## 3. 回传契约

```ts
type PickerResult<T> =
  | { action: 'select'; value: T }
  | { action: 'clear' }
```

统一使用 `src/domains/common/picker.ts` 的 `createPickerChannel`。领域专用选择页只负责自己的模型、过滤和展示，不复制存储实现。

## 4. 验收

- 项目：状态/来源/设计师/常用项目/搜索分页。
- 员工：`company/pages/employee-picker` 支持 `payroll|directory` 来源、角色集合、排除本人、仅在职、搜索分页和一次性回传；来源页禁止自行全量拉员工。
- 工人：`labor/pages/worker-picker` 支持姓名/工种/手机号、状态和数据库分页；工资付款与付款补录必须传 `activeOnly=1`，禁止页面内加载工人数组或选择停用工人。
- 客户已确认报价：`quote/pages/quote-picker` 固定 `Accepted` 状态，支持当前客户/房屋和全部已确认切换、服务端搜索分页；来源页展示客户、房屋、金额、设计师和版本，不显示内部报价编号。
- 供应商：`supply/pages/supplier-picker` 支持合作类型、合作状态、关键词、数据库分页和账期/品牌摘要；停用供应商不能用于新价格。
- 报价库项目：`CatalogPicker` 提供分类树、品牌/规格、关键词和服务端分页；供应商价格页不得用 `size: 200` 或页面内数组。
- 汇报项目：`project/pages/report-project-picker` 支持状态、来源、设计师、关键词和服务端分页；动态页不再用 ActionSheet 选项目。
- 量房房屋：`customer/pages/measure` 通过 `property-picker` 显式选择；多套房不自动默认第一套。
- 员工指派：客户负责人/设计师、项目岗位、项目筛选设计师统一通过 `employee-picker`。
- 内容模板：`content/pages/template-picker` 使用 `content/template/page` 服务端分页。
- 费用分类：`finance/pages/expense-category-picker` 使用 `expense/categories/page` 服务端分页。
- 客户与房屋：多房屋显式选择。
- 账务分类：树层级、方向、启用状态、路径。
- 报价分项：分类树、品牌/系列/规格、区域、数量和价格。
- 统一机制：空、失败、越权、上下文切换、服务端复核。

## 5. 表单分区

- 业务对象选择使用全宽上下文卡片，不参与左右半栏。
- 短字段可以双列；长文本、项目、客户、房屋、应收应付等始终占整行。
- 已选项目卡片展示名称、状态、客户/地址、金额、负责人和阶段；不得用内部编号替代业务身份。
- 已选报价展示客户、房屋、金额、状态、设计师和版本；不得只显示“已选择报价”。
- 已选供应商展示名称、合作状态、合作类型、结算账期和联系人；已选报价库项目展示名称、分类、品牌规格、单位和可报价状态。
- 已选内容模板展示名称、画幅、时长和片段范围；已选费用分类展示名称、说明和基础/企业类型。
- 提交前增加结果预览/确认区，说明本次操作将产生什么结果。
- 结果区不重算正式金额，以服务端为准。

## 6. 单据化表单

应收、应付、收款、付款、合同变更、凭证模板等有稳定单据形态的动作，直接以最终业务对象作为可编辑主界面，不再做“传统字段表单 + 重复预览”。项目等上下文使用全宽卡片，业务参考数据放侧栏或结果区。服务端校验、权限和状态机不变。

## 7. 业务单据视觉层级

- 已选业务对象卡必须满宽且左右信息区对称。
- 长名称可换行，但不得挤压金额、负责人、阶段和操作。
- 固定短枚举可使用 chips、原生选择器或传统 select；应收类型等单据核心类型可放在节点名称下方，使用紧凑 checkbox 视觉组并保持单值。
- 远程业务对象禁止使用 `picker`、`el-select`、可筛选下拉或 `JzSelectField`；必须使用专用选择页或专用业务选择组件。
- 颜色按表单区域整体渐变呈现；输入项和普通字段保持中性。
- 状态标签可使用状态色，颜色不替代文字。

## 8. 存量治理

新页面立即执行；存量按业务主链迁移。当前已完成客户、房屋、设计方案、套餐模板、合同报价来源、员工、工人、供应商和报价库项目主链。

- 合同创建：`src/subpackages/project/pages/create.vue` 已移除客户已确认报价全量数组和显示文本反查，改用 `quote-picker`。
- 供应商采购价：`src/subpackages/supply/pages/partner-price-edit.vue` 已移除供应商全量数组和 200 条报价库项目数组，供应商使用 `supplier-picker`、项目使用 `CatalogPicker`。
- 后端：`quote/page`、`designer quote page`、`partner/page`、`partner-price/page`、`content/template/page`、`expense/categories/page`、`project/project/picker/page`、`plan/template/picker/page` 使用数据库分页；供应商应付摘要按当前页一次聚合，避免 N+1。
- 设计、套餐、报价行选择器已改为数据库分页；项目、套餐和计划选择器移除了逐行 enrich。
- 10× 基准命令：`python3 scripts/benchmark-app-selectors-10x.py benchmark`。23/23 场景 P95 ≤500ms，分页对象 SQL 不随行数增长。
- 全量语义门禁：`npm run audit:selectors` 扫描所有 App Vue 页面中的业务对象 `JzSelectField` 和 ActionSheet；当前硬违规为 0。
- 禁止只做前端替换：后续新增选择器仍须同时检查对应 Provider 的数据范围、分页、关键词、状态和按 ID 回读能力。
