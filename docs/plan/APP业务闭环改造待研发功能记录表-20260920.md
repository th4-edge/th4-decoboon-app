## 1. 目标与结论

装得清 App 本轮改造的目标不是继续增加孤立页面，而是让装企能够在 App 内完成一条真实业务闭环：

```text
客户建档
-> 首联 / 跟进
-> 预约量房
-> 量房 / 录诉求
-> 设计方案
-> 报价
-> 客户接受
-> 设计师发起合同
-> 客户签署
-> 财务登记首期款（不影响生效门禁）
-> BOSS 与财务确认
-> 合同生效
-> 系统创建项目
-> 项目经理接项目
-> 施工任务 / 现场动态 / 材料到场
-> 合同变更
-> 阶段验收 / 业主确认
-> 收款 / 付款 / 成本完整性
-> 项目结算
```

验收口径：

> 装企不打开 Web，仅使用 App 即可完成上述主链；每个状态都有明确下一责任人和 App 内入口。

## 2. 已确认业务口径

| 编号 | 口径 | 研发约束 |
| --- | --- | --- |
| BR-APP-001 | App 优先，Web 暂缓 | 本轮不新增 Web 业务能力；后端保持统一领域模型 |
| BR-APP-002 | 客户用于经营关系，房屋用于实际执行 | 量房、设计、报价、合同、项目和收款节点必须绑定 `customerId + propertyId` |
| BR-APP-003 | 合同必须来源于已接受报价 | 不允许正常业务绕过报价直接创建合同或项目 |
| BR-APP-004 | 设计师可以发起和送签合同 | 设计师不获得合同最终生效权 |
| BR-APP-005 | 合同生效必须同时具备 BOSS 和财务确认 | 两个确认事实独立留痕，不能用一个“已签约”代替 |
| BR-APP-006 | 首期款到账是独立财务事实，不阻断合同生效和项目开工 | 应收、收款、核销和流水必须真实记录；但首期款未到账只显示财务风险，不作为合同生效或首个阶段开工的硬门禁 |
| BR-APP-007 | `Signed` 与 `Effective` 分离 | `Signed` 表示签署事实；只有 `Effective` 能创建项目 |
| BR-APP-008 | 合同签订必须选择收款计划和施工计划 | 模板选择后形成合同级快照，后续模板变更不回写合同 |
| BR-APP-009 | 收款计划由 BOSS、财务配置和确认 | 财务负责金额、日期、节点和到账确认；BOSS 负责商务确认 |
| BR-APP-010 | 施工计划由 BOSS、设计师、项目经理、财务按权限配置 | 财务重点配置阶段与收款触发关系，不修改工程量、销售价和成本 |
| BR-APP-011 | 收款节点可关联施工阶段 | 模板使用稳定阶段编码，合同生成后绑定具体 `ProjectStage` |
| BR-APP-012 | 阶段完成需区分施工完成和验收完成 | 默认收款触发建议为 `StageStatus.Done`，企业可配置为 `Accepting` |
| BR-APP-013 | 签约后主材选材使用文本记录 | 颜色、规格、大小不拆成逐材料结构字段 |
| BR-APP-014 | 主材选材客户确认后才能下单 | 材料计划可生成，但下单前必须存在最新客户确认文本 |
| BR-APP-015 | 工作台是角色行动投影 | 工作台不新建业务状态，不复制金额、进度和权限 |
| BR-APP-016 | 客户+房屋是签约前工作台主键，项目是签约后主键 | 所有跳转必须携带明确对象 ID，禁止列表第一条兜底 |
| BR-APP-017 | 项目进度由任务和阶段派生 | 前端不得直接修改项目进度、成本、已收和利润字段 |
| BR-APP-018 | 成本不完整时利润和毛利率为空 | 页面显示“成本未完整”，禁止按 0 成本伪造利润 |
| BR-APP-019 | 重复动作必须幂等 | 签约、生效、立项、收款、付款、采购、到货、阶段开工和验收不能重复写事实 |
| BR-APP-020 | 错误账务不能物理删除 | 通过调整、冲销、退货或反向流水修正，保留审计链 |
| BR-APP-021 | 全角色引导分为企业启动与岗位启动两层 | Boss 企业启动判断企业是否具备开始业务的基础；员工和业主岗位启动只展示当前角色责任范围内可执行的首任务，不把企业全量事项分发到个人 |
| BR-APP-022 | 引导完成必须由真实领域对象推导 | 每步研发前冻结 `key / label / required / source_provider / completion_predicate / count / refresh_triggers / next_action / exception`；教程点击、本地布尔值和接口 `success=true` 均不能作为完成事实 |
| BR-APP-023 | 引导状态必须支持未知、失败和回退 | 接口失败显示“暂不可确认”；对象新增、编辑、删除或停用后，在首页重新显示、下拉刷新或跨页返回时重新读取；删除后允许由已完成回退为未完成 |
| BR-APP-024 | 必做与可选不得混用 | 可选步骤完成后只展示自身状态，不改变必做分母、不阻塞下一步；必做步骤只能按真实对象谓词完成 |
| BR-APP-025 | 单据导出必须由服务端基于业务快照生成 | 报价、材料、财务和合同导出必须关联业务对象、模板版本、导出时间、操作人、文件指纹和文件地址；不得依赖浏览器自行拼接正式单据 |
| BR-APP-026 | 企业单据格式采用“标准结构 + 企业模板” | 企业维护名称、税号、地址、电话、Logo、开户行、账号和法定代表人等抬头资料；模板版本化，历史单据不随新模板变化 |
| BR-APP-027 | 导出权限必须继承业务权限 | 成本、利润、供应商执行价、银行账号、客户手机号等敏感字段按角色和单据场景裁剪；前端隐藏不能替代服务端导出校验 |
| BR-APP-028 | 系统导出仅是 PDF 打印辅助文件 | 系统生成的报价、材料、财务和合同 PDF 只用于企业线下打印、签署、盖章和留档，不进行实名认证、数字证书、时间戳、电子签章或效力认定；不得表述为电子合同或电子签 |
| BR-APP-029 | 正式单据支持打印、重打和作废控制 | 正式单据必须有唯一编号、模板版本、业务快照、水印和重打次数；作废后不得继续作为有效单据 |
| BR-APP-030 | 财务导出必须区分管理台账与会计核算 | 首期支持资金台账、收款/付款单、应收/应付和项目结算；借贷凭证、科目和总账只有在正式会计口径确认后实现，不冒充法定会计总账 |
| BR-APP-031 | 导出、预览和批量打印按端分工 | App 负责预览、分享、申请导出和查看文件；Web 负责企业模板维护、批量导出、打印预览、盖章位和打印审计。所有端使用同一后端单据快照 |
| BR-APP-032 | 单据必须提供行业模板基线并支持免配置使用 | 平台内置行业标准报价、材料、财务和合同打印模板；企业未配置时直接使用平台基线，不得出现空白模板或强制先配置 |
| BR-APP-033 | 企业模板首期采用标准版、字段配置和受控样式调整 | 企业可调整字段显隐、顺序、Logo、品牌色、字体字号、边距、页眉页脚、页码、表格样式和盖章位；首期不支持任意 HTML、脚本或上传 Word/PDF 底稿 |
| BR-APP-034 | 首期盖章位是空白区域，不生成印章 | PDF 只保留空白盖章位，由企业线下打印后实物盖章；系统不插入印章图片、数字印章或电子签章 |
| BR-APP-035 | 门店维度后期按批次全局铺开，禁止单点添加 | 门店是租户内的经营维度，不是单个 Tab 的功能。用户已裁决（2026-09-21）：本轮先登记需求，后续在客户、房屋、设计、报价、合同、项目、财务、报表和全部经营指标中统一引入门店筛选与门店口径（`company → store → team → owner`），并统一门店快照与转店规则；不允许只在一个页面加门店筛选，否则同一事实会出现两套口径 |
| BR-APP-036 | 企业负责人项目经营 Tab 的指标与毛利口径 | 指标卡固定为「在建项目 / 在建合同额 / 回款率 / 本月新签项目」；分段支持「按项目状态」与「按合同履约（全部 / 待签约 / 履约中 / 已完成）」双维度；毛利按**实际成本口径**展示（实际成本 + 毛利 + 毛利率），成本不完整时毛利为空并显示「成本未完整」，禁止 0 成本伪利润 |

## 3. 角色与权限定义

| 角色 | 主要职责 | 关键权限边界 |
| --- | --- | --- |
| BOSS | 企业配置、合同商务确认、施工计划配置、经营风险 | 企业范围；不能绕过状态机直接改财务余额 |
| 门店店长 | 门店范围项目协同、客户和员工管理 | 财务当前只读；合同最终生效权待业务另行授权 |
| 团队负责人 | 团队客户、设计调度、项目风险 | 团队范围；不能代替业主确认或财务记账 |
| 业务员 | 首联、跟进、预约量房、客户交接 | 本人客户；报价、合同、项目只读 |
| 设计师 | 量房、设计、报价、合同发起、施工计划、主材选材 | 本人/项目参与范围；不能单独确认合同生效 |
| 项目经理 | 项目配置、阶段/任务、现场动态、材料风险、验收提交 | 本人负责项目；不能代替业主确认 |
| 履约/材料人员 | 材料计划、采购、到货、库存协同 | 项目参与范围；财务写权需另行授权 |
| 财务 | 收款计划、首期款、应收账款、应付、付款、台账、结算 | 企业财务范围；合同最终生效需与 BOSS 共同确认，首期款到账不是生效门禁 |
| 业主客户 | 查看本人项目、确认报价/变更/选材/验收 | 仅本人数据；不可见成本、利润和内部财务 |
| 平台运营 | 维护平台基线包和平台通用模板 | 仅平台域；不得直接修改企业业务事实 |

## 6. 核心模块研发拆解

### 6.0 全角色启动引导（APP-ONB）

目标：把“用户找不到功能”改为“系统根据当前角色、责任范围和真实对象状态给出下一步”。启动引导不是产品教程，不记录“我已阅读/我已点击”作为完成事实。

#### 6.0.1 两层模型

| 层级 | 适用对象 | 业务范围 | 完成口径 |
| --- | --- | --- | --- |
| 企业启动引导 | BOSS | 企业注册后具备开始第一份客户业务的 3 项基础能力 | 报价项目、标准成本、客户及房屋均由真实对象推导；首份报价、签约和立项不进入该分母 |
| 岗位启动引导 | 店长、团队长、业务员、设计师、PM、履约/材料、财务、业主 | 首次进入岗位后，完成当前责任范围内的首个有效业务动作 | 由当前角色可见的真实业务事实推导；没有责任对象时展示等待分配或岗位空态，不伪造完成 |

#### 6.0.2 角色首任务矩阵

| 角色 | 首次出现条件 | 首任务业务目标 | 建议完成谓词 | 下一步入口 | 异常态 |
| --- | --- | --- | --- | --- | --- |
| BOSS | 企业注册完成 | 完成报价基础、客户房屋和岗位启动 | 有效报价项目 ≥ 1；正数标准成本 ≥ 1；客户且至少关联 1 套房屋 ≥ 1 | 当前首个未完成步骤 | 接口失败显示“状态暂不可确认” |
| 门店店长 | 加入门店或首次登录 | 确认门店成员、客户负责人和设计调度 | 本店存在有效成员或客户责任事实；具体必做谓词待业务冻结 | 门店客户/团队/设计调度 | 无门店数据时显示等待配置 |
| 团队负责人 | 加入团队或首次登录 | 确认团队客户分配和设计派单 | 团队存在有效成员或客户责任事实；具体必做谓词待业务冻结 | 团队客户/团队派单 | 无团队数据时显示等待配置 |
| 业务员 | 加入企业或被分配客户 | 完成客户建档、房屋、首次跟进和量房预约 | 客户 ≥ 1 且关联房屋 ≥ 1；首次跟进事实已写入；量房预约状态可读取 | 新建客户/客户详情/预约量房 | 任何来源接口失败不得显示“已完成” |
| 设计师 | 被指派房屋或首次登录 | 完成诉求、方案、报价或签约推进 | 当前责任房屋存在诉求/方案/报价事实，按工作台下一状态推进 | 设计/报价/签约工作台 | 无责任房屋时显示等待设计调度 |
| 项目经理 | 合同生效后项目生成或首次登录 | 接项目、确认计划并开工首个阶段 | 项目已指派 PM；计划已确认；首个可执行阶段可读取 | PM 工作台/项目计划/阶段 | 未指派项目时显示“已签约待接单”，不得空列表 |
| 履约/材料人员 | 项目参与或被分配材料任务 | 处理材料计划、采购和到货 | 存在项目材料计划或采购/到货事实，按当前状态推进 | 项目/供应商协作/采购 | 无参与项目时显示等待项目分配 |
| 财务 | 加入企业或首次登录 | 处理应收、收款、应付和成本完整性 | 存在当前财务范围内的应收/应付事实，按状态推进 | 财务工作台/项目账本 | 成本不完整时显示“成本未完整” |
| 业主客户 | 接受邀请并绑定项目 | 查看本人项目、动态和待确认验收 | 存在有效项目授权；有待验收时优先展示确认动作 | 我的家/动态/验收 | 邀请失效或授权撤销时不得展示旧项目数据 |

#### 6.0.3 两个真实场景

场景一：新成立 15 人单店装企

```text
BOSS 注册企业
-> 首页显示企业启动引导
-> 完成报价项目和标准成本
-> 建立第一个客户及房屋
-> 邀请店长、业务员、设计师、PM 和财务
-> 各角色首次登录只看到本岗位首任务
-> BOSS 企业启动引导自动隐藏，岗位引导按各自责任继续
```

异常：报价项目接口失败时，BOSS 看到“状态暂不可确认”，不得显示确定未完成；客户已建但没有房屋时，客户步骤不得完成。

场景二：存量装企新增项目经理

```text
BOSS 邀请 PM
-> PM 接受邀请并登录
-> 系统检查项目指派关系
-> 存在“已生效未接单”项目时优先展示待接项目
-> PM 接项目、确认计划、开工首个阶段
-> PM 引导自动进入施工管理状态
```

异常：PM 没有被指派任何项目时，显示“等待项目分配”，不得通过项目列表首屏数据推断完成或展示其他门店项目。

#### 6.0.4 研发约束

- 引导数据源必须覆盖全量事实，不能用首页分页条数代替总数。
- 引导卡片返回首页、下拉刷新、跨页写入后必须重新读取。
- `done`、`unknown`、`failed`、`not_applicable` 必须分开表达。
- 业务对象删除、停用或责任关系撤销后，引导完成状态必须回退。
- 岗位引导不得越过数据权限展示企业全量对象，服务端必须再次校验。
- 首个报价、首个签约和首个项目属于后续业务里程碑，不回头占用企业启动引导分母。

#### 6.8.3 导出权限和快照

- 导出必须使用服务端业务快照，不能直接导出前端页面字段；
- 客户报价 PDF、供应商单据和内部成本报表必须是不同导出定义；
- 首发以 PDF 为主，Excel/CSV 仅作为内部数据整理的可选补充，不作为正式打印稿的替代；
- 导出记录必须包含 `company + businessType + businessId + templateVersion + snapshotHash + fileUrl + createdBy + exportedAt`；
- 同一对象重复导出可以生成新文件，但不能改变原始业务事实；
- 批量导出、超大文件和异步导出必须记录任务状态、失败原因和过期时间；
- 导出文件使用私有 OSS 和短期下载授权，访问前再次校验企业、角色和对象归属；
- App 提供预览、分享和下载入口；Web 提供模板维护、批量导出、正式打印和空白盖章位，不能因为支持 App 就把打印能力硬塞进小程序。

#### 6.8.4 PDF 打印与线下签署、盖章

```text
生成可打印 PDF
-> 预览和检查
-> 线下打印
-> 人工签署 / 实物盖章
-> 可选上传扫描件归档
```

系统边界：

- PDF 是企业业务文件的打印版本，不是电子合同、电子凭证或电子签；
- 系统不执行实名认证、数字证书、时间戳、电子签章和效力认定；
- 合同 PDF 可以保留签字栏和盖章位，企业在线下完成人工签署与实物盖章；
- 首期模板只提供空白盖章位，不插入印章图片、数字印章或电子签章；
- 打印和重打必须记录操作人、时间、模板版本和业务对象；
- 线下签署后的扫描件可以作为附件归档，但不能替代业务状态推进事实。

#### 6.8.7 两个真实场景

场景一：装企给客户发送正式报价单

```text
设计师完成报价
-> 选择企业报价单模板
-> 生成不含成本利润的客户 PDF
-> BOSS/财务按权限生成内部 PDF
-> 打印或分享客户版
-> 系统记录导出人、模板版本和文件哈希
```

异常：设计师或客户版导出不得出现标准成本、毛利和内部供应商价格。

场景二：财务打印收款凭证和月度流水

```text
财务核对应收和收款核销
-> 生成收款单 PDF
-> 使用企业模板和空白盖章位
-> 打印 / 盖章
-> 重打时记录次数
-> 导出月度资金流水
-> BOSS 按企业范围核对
```

异常：跨企业、跨门店或未授权财务数据不能进入导出文件；账户和客户隐私字段按导出目的裁剪。

## 8. 状态与数据规则

### 8.1 合同

```text
PendingSign
-> Signed
-> Effective
-> Changing / Changed
-> Completed
-> Settled
```

条件：

- `Signed`：客户签署事实；
- `Effective`：BOSS、财务确认齐备；首期款到账不是必要条件；
- `Effective` 后创建项目；
- `currentAmount = signedAmount + 已确认变更金额`。

### 8.2 应收

```text
待触发
-> Pending
-> Partial
-> Received
-> Overdue / Closed
```

- 首期款节点可在合同阶段创建；
- 阶段节点在触发后生成或激活；
- 收款不能超过应收余额；
- 收款幂等；
- 合同变更后只调整未来未收节点。

### 8.3 施工计划

```text
系统初排
-> PM 确认
-> 计划基线
-> 当前计划
-> 实际执行
```

- 模板变化不回写历史合同；
- 阶段改名通过稳定编码保持收款关联；
- 已施工任务不因减项被删除。

### 8.4 主材选材

```text
Draft
-> CustomerConfirmed
-> Superseded
```

- 客户确认是下单前置；
- 新旧版本保留；
- 不改变合同、报价和成本快照。

## 9. 异常与反向用例

必须覆盖：

1. 设计师尝试单独让合同生效 -> 拒绝。
2. 合同和收款计划未经 BOSS、财务确认，单独确认 -> 不能生效。
3. 重复提交签约和生效 -> 不重复创建项目。
4. 同一报价重复立项 -> 返回原项目或拒绝。
5. 同一房屋多套方案出现多个有效项目 -> 阻断并提示。
6. 收款金额超过应收余额 -> 拒绝。
7. 重复收款/付款/到货 -> 幂等处理。
8. 材料计划没有客户确认选材 -> 禁止下单。
9. 已施工任务被合同减项 -> 保留现场事实，生成差异。
10. 阶段刚开始但错误触发进度款 -> 状态校验拒绝。
11. 阶段改名后收款节点丢失 -> 通过阶段编码保持关联。
12. 成本不完整时显示利润 -> 禁止，显示“成本未完整”。
13. 跨企业、跨门店、跨项目访问 -> 403/404，不泄露存在性。
14. 员工用自己账号代替业主确认 -> 拒绝或按线下代录规则留证并复核。
15. 模板修改后历史合同金额变化 -> 禁止，使用合同快照。
16. 引导接口失败 -> 显示状态暂不可确认，不得折叠成确定未完成或已完成。
17. 客户已建但未建房屋 -> Boss 企业启动引导的客户步骤不得完成。
18. 删除、停用或撤销责任关系后重复进入首页 -> 已完成引导必须重新收敛为未完成或不再适用。
19. 岗位引导越权读取其他门店、团队或项目对象 -> 服务端拒绝，前端不得展示。
20. 报价客户版导出包含成本、利润或内部备注 -> 禁止，按导出模板和角色双重裁剪。
21. 企业 A 使用企业 B 的单据模板或印章资料 -> 禁止，模板和文件必须按企业隔离。
22. 系统生成的 PDF 被表述为电子合同、电子签或具有法律效力的文件 -> 禁止，必须标记为线下打印辅助稿。
23. 重复打印或作废后继续使用原单据 -> 记录重打次数、作废原因，并禁止作废件继续作为有效单据。
24. 导出后业务数据变化导致历史单据金额漂移 -> 使用导出快照、模板版本和文件哈希保持可追溯。

## 10. 验收场景

### 场景 A：单店整装标准闭环

```text
建客户
-> 建房
-> 量房
-> 设计
-> 报价
-> 客户接受
-> 设计师发起合同
-> BOSS+财务确认
-> 项目创建
-> PM 开工
-> 财务登记首期款（不阻断生效和开工）
-> 选材确认
-> 材料下单
-> 任务留证
-> 阶段验收
-> 收款和结算
```

### 场景 B：多房屋 + 合同变更

验证：

- 客户一套房屋进入签约，另一套仍在设计；
- 合同签后发生增项；
- 已开始任务保留原事实；
- 未来应收和施工计划同步调整；
- 项目、合同、应收、成本金额可解释。

### 场景 C：全角色启动与状态收敛

验证：

- 新企业 Boss 完成 3 项必做后，引导自动隐藏；
- 员工接受邀请后进入对应岗位首任务，不展示全公司菜单；
- 业主只看到本人已授权项目；
- 接口异常显示未知态，删除对象后完成状态回退；
- 供应商和成员邀请为可选，不改变必做分母。

### 场景 D：PDF 导出与线下打印

验证：

- 企业未配置时直接使用平台行业模板基线；
- 不同企业可配置不同抬头、Logo、税号、开户行和空白盖章位；
- 客户报价 PDF 不含成本利润，内部 Excel 按权限包含成本；
- 材料计划、采购单、到货单和供应商对账单可按企业模板打印；
- 财务收款、付款、台账和月度汇总导出后与系统余额一致；
- 正式单据打印、重打、作废和扫描归档均有记录；
- 合同 PDF 可用于线下打印、人工签署和实物盖章，但不生成电子合同或电子签。

### 场景 E：异常与负向

验证：

- 首期款未到账不能阻断合同生效和首个阶段开工。
- 角色越权不能操作；
- 重复请求不重复记账；
- 选材未确认不能下单；
- 结算未满足条件不能关闭；
- 样板数据不进入正式报表。

## 12. 当前已知风险和待确认项

| 风险/问题 | 影响 | 处理建议 |
| --- | --- | --- |
| 当前合同签约/生效代码只有 BOSS 可写 | 与设计师发起、BOSS+财务确认口径冲突 | 先冻结角色和能力点，再改 Provider |
| 当前收款计划固定 30%/40%/30% | 无法适配不同企业付款节点 | 改为企业模板+合同快照；收款计划本身不成为开工门禁 |
| 合同阶段与项目阶段的收款计划衔接不完整 | 首期款和后续应收容易出现时间口径不一致 | 允许合同阶段先建立收款计划，但首期款到账不阻断合同生效和首个阶段开工 |
| 当前没有施工计划模板 | 施工计划来源不可解释 | 建立模板和合同快照 |
| 当前选材文本未形成下单门禁 | 可能绕过客户确认直接采购 | 增加 MaterialSelection 和下单校验 |
| 付款/采购/到货幂等覆盖不足 | 重复记账风险 | 增加幂等键和唯一约束 |
| 系统只支持管理会计台账 | 不能等同于法定财务总账 | 明确产品边界，不承诺税务/总账能力 |
| Web 与 App 状态投影可能不一致 | 跨端口径偏差 | 后续以同一后端事实源统一 |
| 历史脏数据缺失归属 | 项目、财务和权限异常 | 进入待确认清单，不自动猜测 |
| 当前没有统一导入批次和期初余额模型 | 历史客户、项目和财务数据无法安全进入系统 | 按 `APP-FLOW-001/004` 建立导入批次、预览、幂等和期初开账；期初月结前可重导 |
| 历史合同无法重建完整报价 | 直接补报价会产生虚假设计、成本和历史结算事实 | 历史合同只保存签署扫描件、合同金额基线和项目关联，不生成报价行、成本或利润 |
| 合同生效、项目生成和 PM 交接之间没有就绪门禁 | 容易形成“已签约无人接单”或重复开工 | 按 `APP-FLOW-002/003` 建立派生交接清单和 PM 开工门禁 |
| 当前没有统一 PDF 渲染和归档记录 | 报价、合同、材料和财务无法形成可审计打印件 | 按 `APP-FLOW-005` 建立模板解析、渲染、哈希和归档 |
| 当前财务事实由业务动作分散写入，没有统一事件记录 | 并发重试和状态回退可能造成重复应收、应付或流水 | 按 `APP-FIN-004` 建立事件幂等、来源追踪和失败重试 |
| 当前缺少自动核校和月结锁定 | 老板看到的合同、应收、收款、应付和成本可能口径不一致 | 按 `APP-FIN-007/008` 建立核校中心和期间锁定 |
| 当前预计成本、承诺成本、实际成本和已付金额没有统一展示 | 容易把付款金额误当实际成本，影响项目利润判断 | 按 `APP-FIN-006` 建立四层成本视图 |
| 当前只有 Boss 首次入驻，其他角色无岗位引导 | 新员工首次登录找不到行动入口，岗位主链无法形成 | 按 `APP-ONB-002/003` 增加全角色岗位启动和业主启动 |
| 引导状态使用空数组或首页条数推导 | 接口失败、超分页或对象删除时会显示错误完成状态 | 按 `APP-ONB-004` 提供全量状态投影、未知态和刷新回退 |
| 报价导出当前为 Web 端 CSV，其他单据无统一导出 | 无法满足企业打印、盖章、归档和财务交接 | 建立 `APP-EXP-001～006` 和统一单据渲染/文件中心 |
| 企业实体缺少税号、开户行、法定代表人等单据抬头字段 | 正式报价、财务单和合同无法按企业格式打印 | 建立企业单据资料模型，不塞入通用 `Setting` 字符串 |
| 当前没有统一 PDF 渲染与打印能力 | 报价、材料、财务和合同无法按企业版式输出线下文件 | 建立 PDF 渲染、模板版本和打印记录，不建设电子签 |
| 财务科目和借贷凭证口径未冻结 | 无法确定导出的是管理台账还是会计凭证 | 首期只做管理台账和收支单据，借贷凭证另行业务裁决 |
| 候选合同 PDF 引用《中华人民共和国合同法》 | 该法已被民法典体系替代，直接作为合同基线存在内容过期风险 | 法务复核条款，更新法律依据后再形成平台合同模板版本 |
| 候选合同含身份证号码、电话和地址等个人信息栏 | 直接复制模板可能产生隐私和存储风险 | 默认模板只保留空白字段和格式，具体信息按业务导入控制 |
| 候选合同页脚为“10页”，PDF 实际12页 | 模板页数、附件结构和打印分页可能不一致 | 冻结模板资产时统一页码、附件和签署页规则 |

## 13. 研发完成定义

一个功能只有同时满足以下条件，才可在本表中标记为“完成”：

- 业务规则已冻结并关联到本表功能编号；
- App 页面入口可从对应角色工作台进入；
- 服务端权限、状态机、金额和幂等校验完成；
- 前端展示加载、空、错误、阻塞和恢复状态；
- 正常链、异常链、越权链和重复链有测试；
- 关键业务事实可以在 App 内重新进入后正确恢复；
- 不依赖 Web 完成关键业务步骤；
- 有可复核的联调证据和独立验收结论。
