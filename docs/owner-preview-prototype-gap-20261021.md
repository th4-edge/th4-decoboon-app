# 业主端 10-14 高保真原型与当前小程序差异审计

- 日期：2026-10-21
- 原型：`输出/草稿/业主端视角重构原型-20261014/index.html`
- 当前实现：`src/pages/index/index.vue`、`src/pages/project/list.vue`、`src/pages/dynamic/index.vue`、`src/pages/mine/index.vue`
- 当前实现说明：`docs/owner-home-v2-handoff-20261021.md`

## 结论

10-14 原型确认为当时的业主端高保真设计版本，但当前小程序不是该原型的代码落地。

当前实现的定位是：

> 在旧业主页面和既有 API 上做业主首页 V2 轻量改版，并修正员工预览入口，让员工进入真实业主页面。

它不是：

> 按 10-14 原型的导航、首屏叙事和信息架构进行重构。

因此当前只能说“员工复用了业主端真实页面”，不能说“已还原 10-14 设计原型”。

> 2026-10-21 更新：`OWNER-UI-V1` 已完成第一轮产品化落地，四主 Tab + 中央装修历程、
> 产品化首页、施工节点、我的钱、家档案和深色装修历程已进入微信开发者工具走查。
> 仍未实现“未来 7 天计划”、逐项验收点、质保/隐蔽工程归档等需要进一步业务裁决的区块。

## 核心差异

| 维度 | 10-14 原型 | 当前小程序 |
| --- | --- | --- |
| 主导航 | 4 个主 Tab + 中间凸起“装修历程”：我的家 / 进度 / 装修历程 / 我的钱 / 家档案 | 我的家 / 进度 / 动态 / 我的，没有中间价值入口 |
| 首屏主句 | “水电改造已完成，等你验收” | “我的家 · 项目进展 / 当前阶段 / 0%” |
| 首屏任务 | 待确认验收、接下来 7 天、需要业主做什么 | 项目卡、8 类档案入口、动态和项目列表 |
| 信息组织 | 按业主心理与下一步任务组织 | 按业务对象与功能入口组织 |
| 进度表达 | 计划 vs 实际、今天、谁上门、是否需要到场 | 百分比、当前阶段、计划完工日期 |
| 钱与档案 | “我的钱”“家档案”独立主页面 | 付款计划、合同档案作为八宫格入口 |
| 视觉语言 | 强叙事 Hero、时间线、沉浸式装修历程、5 槽特殊 TabBar | 常规白色卡片、线性图标、标准四 Tab |
| 数据要求 | 未来 7 天、逐项验收、质保、隐蔽工程、档案保留期等 | 主要复用现有项目、验收、动态和档案入口数据 |

## 差距形成原因

1. 10-14 原型是方向验证稿，不是冻结后的研发需求包。
2. 原型 README 明确列出 6 项必须业务裁决后才能编码的空白，包括未来计划口径、验收点来源、诉求对象、复验、档案权属和隐蔽工程强制点。
3. 后续没有形成“原型区块 → 小程序组件 → API/领域事实 → 验收用例”的逐项落地矩阵。
4. 10-21 交付目标变成了“修正员工预览入口”和“业主首页 V2 轻改”，没有重新确认要按原型重构。
5. 当前四项产物虽然复用真实四 Tab，但中间凸起的“装修历程”入口、我的钱、家档案和首屏任务叙事均未实现。

## 后续建议

若确认 10-14 原型是目标设计，不应继续在现有页面上堆 CSS，应按以下批次推进：

1. **导航与视觉骨架**：四主 Tab + 中间“装修历程”入口，冻结五槽布局和暗色历程层。
2. **我的家首屏**：真实当前任务、待确认验收、下一步、进度是否正常；禁止演示数据。
3. **进度页**：计划 vs 实际、今天、责任人、是否需要业主到场。
4. **我的钱与家档案**：按原型重建信息架构。
5. **数据补齐**：未来 7 天、逐项验收、质保、隐蔽工程和档案权属，先经业务智能体裁决并形成 API 契约。

在完成上述落地前，员工预览只能标记为“真实业主页面复用通过”，不能标记为“10-14 设计原型还原通过”。
