# 装得清小程序端 UI 合规审计报告（2026-09-18）

## 一、概述



* **审计范围**：th4-decoboon-app 全部 74 个页面（主包 13 + 分包 61）。

* **审计方法**：静态代码分析，对照 `AGENTS.md` 第 4（Design Token）/5（硬性视觉规则）/7（交互规范）/11（禁止事项）/15（客户详情专项）节。

* **判定基准说明**：当前 Token 真源是 `src/uni.scss` 的 `$jzb-*`（青绿主色 `#16A394`，深一档 `$jzb-primary-dark:#0E8A7D`），**不是** `AGENTS.md` 第 4 节目标 `$brand-*` 墨绿色系（`#2F7D5A`）。运行时色值另见 `src/styles/tokens.ts` 的 `TOKEN_COLOR`。本报告「是否硬编码」以 `$jzb-*` 为基准 —— 凡是与 `$jzb-*` 同义却写成字面量 hex 的，一律按硬编码处理；与 `$jzb-*` 完全无关的 Ant Design / 灰板色，同时登记为「色板泄漏」。

* **总体结论**：74 页中无「干净页面」，但问题高度集中在两类：① JS / 模板里 `JzIcon color="#HEX"` 字面量泛滥（与 `$jzb-*` 同义）；② 非 8 倍数间距 / 圆角 / 字号遍地。三态（loading/empty/error）在 list 类页面已形成标杆（`customer/list`、`project/list`、`message/list`、`finance/ledger` 等），但 finance/team/statistic/company 多个详情与表单页仍缺骨架与错误重试。客户详情页已基本满足 §15 专项基准，主要遗留是同页多圆角与少量未走 `TOKEN_COLOR` 的图标色。另有 1 个真实业务 BUG：`customer/tag-manage.vue` L22 角色拼写小写导致店长字典维护区永不显示。

## 二、系统性问题（跨页共性，不在每页重复）



1. **品牌色未按规范迁移**

* 现象：当前 `$jzb-primary:#16A394` 青绿；`AGENTS.md` 第 4 节目标是 `$brand-500:#2F7D5A` 墨绿。规范文档与代码真源不一致。

* 建议：需产品 / 设计决策二选一：① 迁品牌色（同步换 `$jzb-*` 全部色阶与 `JzBrandLogo` 视觉）；② 修订 `AGENTS.md` 第 4 节，把 `$brand-*` 目标值改为当前青绿真源。在决策落地前，禁止页面自行引入第三套品牌色。

1. **JS / 模板里 JzIcon color 硬编码 hex 泛滥**

* 现象：约 60+ 处直接传 `#0E8A7D / #FFFFFF / #778390 / #AEB8C2 / #465260 / #6958C8`，实际分别等于 `$jzb-primary-dark / $jzb-text-inverse / $jzb-text-3 / $jzb-text-4 / $jzb-text-2 / $jzb-purple`。

* 建议：`customer/detail.vue` 已正确引入 `@/styles/tokens` 的 `TOKEN_COLOR` 做映射 —— 应全站照此收敛。建议在 `JzIcon` 组件层增加语义别名 prop（如 `color="primaryDark"`），或至少在每个页面 `<script setup>` 顶部 `const c = TOKEN_COLOR` 后统一 `:color="c.primaryDark"`。

1. **Ant Design / 非品牌色板泄漏**

* 现象：`#86909C / #FA8C16 / #722ED1 / #13C2C2 / #F53F3F / #00B42A / #2F54EB / #FF7D00 / #5B6BD6 / #8B93A1 / #1D2129 / #1F2937 / #C9CDD4` 等出现在 JS map（`colorOf / STATUS_META / summaryTag / TYPE_COLOR / costRows / metricCard`）中，既不是 `$jzb-*` 也不是品牌色。

* 建议：新建 `src/styles/tokens.ts` 语义色映射表，按语义命名（primary /success/warning /danger/purple /info/text-1..4 /inverse），JS 侧只引用语义 key；删除散落 hex map。

1. **Token 真源自身偏差**

* 现象：`$jzb-space-2:12rpx`、`$jzb-page-pad:28rpx`、圆角 8/12/20/28/36rpx（含 20/28/36 非 8 倍数）、字号 22/26/30/42/50rpx，与 `AGENTS.md` §5.1「间距 8 倍数」、§4.3 `$page-gutter:32rpx`、§4.4 圆角 4/8/16/24/32/9999 不一致。

* 建议：先在 `uni.scss` 内对齐：`$jzb-page-pad:32rpx`、`$jzb-space-2:16rpx`；圆角刻度统一为 8/12/20/28/36/999（保持现有 28/36 不变，把 20 视为 base）。对齐后再逐页清扫字面量。

1. **statusMeta / TYPE\_COLOR 在 company 多页重复硬编码**

* 现象：`company/members.vue` L24-28 与 `company/member-detail.vue` L21 各自定义一份员工状态色；`message/list.vue` L25-28、`quote/list.vue` L40-50、`quote/detail.vue` L28-33、`subscription/index.vue` L32-43/L225-234 各自定义业务状态色。

* 建议：抽到 `src/domains/identity/meta.ts`（员工状态 / 角色色）或 `src/styles/tokens.ts`（业务状态→语义 token key）单一真源，页面只 import 不重定义。

1. **公共组件复用不均**

* 现象：`message/list`、`project/list`、`customer/list` 是三态标杆（`PageState` + `JzSkeleton` + `JzEmpty` + `ListFooter`）；但 `finance/partners`、`team/list`、`team/workbench`、`statistic/analysis|assessment|performance`、`company/*` 多个详情页缺 `JzSkeleton` 骨架与 error 重试，失败仅 `toastError`。

* 建议：按「loading 骨架 + error 重试」两个最小补丁补齐：初载 `JzSkeleton`，失败 `PageState state="error" @retry`。空态仍走 `JzEmpty`。

1. **品牌 Logo 违规使用**

* 现象：`company/info.vue` L41 用 `building` 图标 + `#FFFFFF` 冒充企业 / 品牌 Logo。

* 建议：违反 `AGENTS.md` §1 强制规则。改用 `<JzBrandLogo variant="white" />`（深色品牌背景）。
