## 2. 阻塞项：`wx.modelContext` 被 uni-app 运行时丢弃

### 2.1 根因源码

`node_modules/@dcloudio/uni-mp-weixin/dist/uni.api.esm.js`：

```js
const objectKeys = [
    'qy', 'env', 'error', 'version', 'lanDebug', 'cloud',
    'serviceMarket', 'router', 'worklet', '__webpack_require_UNI_MP_PLUGIN__',
];
const launchOption = wx.getLaunchOptionsSync ? wx.getLaunchOptionsSync() : null;

function isWxKey(key) {
    if (launchOption && launchOption.scene === 1154 && singlePageDisableKey.includes(key)) {
        return false;
    }
    // 关键：只有"白名单命中"或"原生类型是 function"才被保留
    return objectKeys.indexOf(key) > -1 || typeof wx[key] === 'function';
}

function initWx() {
    const newWx = {};
    for (const key in wx) {
        if (isWxKey(key)) {
            newWx[key] = wx[key];
        }
    }
    if (typeof globalThis !== 'undefined' && typeof requireMiniProgram === 'undefined') {
        globalThis.wx = newWx;   // 直接把全局 wx 替换掉
    }
    return newWx;
}
```

两个要点：

1. **判定条件是"函数型"兜底**：`typeof wx[key] === 'function'`。`wx.modelContext` 是**对象**（`wx.modelContext.getContext()`），白名单里也没有它 → 被丢弃。
2. **全局被替换**：`globalThis.wx = newWx`。所以连 `globalThis.wx.modelContext` 这条退路也被切断。
3. `initWx()` 在文件中被调用**两次**（`wx$2`、`wx$1`），第二次遍历的是已被替换过的全局 wx，因此任何修复都必须对两次调用都成立。

### 2.2 复现结果（`node:vm`，忠实还原小程序全局语义）

| 场景 | 第一次 `initWx` 后 | 第二次 `initWx` 后 | 结论 |
| --- | --- | --- | --- |
| 现状（未打补丁） | `undefined` | `undefined` | ❌ 丢失 |
| 补丁 A：把 `modelContext` 加进 `objectKeys` | `object` | `object` | ⚠️ 仅在 `wx.modelContext` 可枚举时有效；不可枚举则仍丢失 |
| 补丁 B：循环后显式补齐 | `object` | `object` | ✅ 两种情况都有效（推荐） |

### 2.3 全部 AI API 的存活情况

| API | 原生类型 | 经 uni 运行时 |
| --- | --- | --- |
| `wx.modelContext` | object | ❌ **丢失** |
| `wx.onAgentHandoff` | function | ✅ 保留 |
| `wx.offAgentHandoff` | function | ✅ 保留 |
| `wx.requestAgentPrivacyAuthorization` | function | ✅ 保留 |
| `wx.getDetailPageCloseButtonBoundingClientRect` | function | ✅ 保留 |

也就是说：**只有 `modelContext` 这一个挂掉，而它恰好是半屏接力页回写对话的唯一通道。**

### 2.4 升级能否解决：不能

对照 npm 上最新的 vue3 alpha `3.0.0-alpha-5030120260930001`（2026-09-30）：

- `objectKeys` 与当前版本**完全一致**，没有 `modelContext`；
- 全包 `grep modelContext` **零命中**。

结论：**升级 uni-app 不能绕过此问题**，必须打补丁或规避用法。

## 4. 精确修复方案

### 4.1 补丁内容（`patch-package` 格式，目标文件 `dist/uni.api.esm.js`）

```diff
--- a/node_modules/@dcloudio/uni-mp-weixin/dist/uni.api.esm.js
+++ b/node_modules/@dcloudio/uni-mp-weixin/dist/uni.api.esm.js
@@
     const newWx = {};
     for (const key in wx) {
         if (isWxKey(key)) {
             // TODO wrapper function
             newWx[key] = wx[key];
         }
     }
+    if (wx.modelContext && !newWx.modelContext) {
+        newWx.modelContext = wx.modelContext;
+    }
     if (typeof globalThis !== 'undefined' &&
         typeof requireMiniProgram === 'undefined') {
         globalThis.wx = newWx;
     }
     return newWx;
 }
```

**为什么用显式补齐而不是加进 `objectKeys`**：`objectKeys` 依赖 `for...in` 枚举，若微信把 `wx.modelContext` 定义为不可枚举属性就会失效；显式赋值读的是属性本身，两种情况都成立。同时它对 `initWx()` 的两次调用都成立。

## 5. 影响范围与仍存不确定性

### 5.1 确定受影响（必须靠补丁）

在小程序运行时（即 uni-app 编译产物内）访问 `wx.modelContext` 的代码：

- **半屏接力页**：`wx.modelContext.getContext().reapplyApiCall({ arguments })`、`sendFollowUpMessage({ content })` —— 官方明确"半屏页面的运行环境与小程序的运行环境完全一致"，因此走的就是被替换后的 wx；
- 任何在 `.vue` / `.ts` 模块中直接调用 `wx.modelContext.*` 的业务代码。

### 5.2 待真机确认（补丁可一并消除风险）

官方《运行机制》说明：原子接口、原子组件、实时动态原子组件运行在**微信客户端创建的独立 JS 执行上下文**中，"该环境与小程序的运行环境不同"，且三个上下文**不共享全局变量**。

由此推论：**SKILL 的 `apis/` 与 `components/` 代码可能根本不受 uni-app 全局替换影响**（它们不经过 uni 运行时）。

- 若成立：补丁只对"半屏接力页"这条路径是必需的；
- 若不成立（例如开发工具或某些设备复用同一上下文）：补丁对整个 SKILL 都是必需的。

**两种情况补丁都是正确且无害的**，因此建议直接打，不必等真机结论；真机只用于确认影响面表述。

### 5.3 其他未验证项

| 项 | 原因 |
| --- | --- |
| 真实 `wx.modelContext` 运行时可用性 | 需先在小程序后台「基础功能 - AI 能力」申请**开发模式**通过，且真机 iOS 微信 ≥ 8.0.74、基础库 3.16.1、开发者工具 Nightly |
| 原子组件在 glass-easel 下的渲染效果 | 同上；且官方文档标注"暂不支持调试" |
| 评测四项指标 | 需开通后用官方评测插件自测 |
