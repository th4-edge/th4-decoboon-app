# 装得清 App · UI / 交互 / 布局设计规范

> 适用范围：`th4-decoboon-app` 微信小程序与 H5  
> 品牌主色：`#16A394`  
> 设计目标：专业、克制、可信、易执行。面向装修企业老板、顾问、设计师、项目经理、监理、采购、仓管、财务和业主，不以“传统后台”或“表单堆叠”为视觉方向。

---

## 1. 设计原则

### 1.1 角色优先

- 不同角色进入不同工作台，功能入口由角色和权限决定。
- 页面首屏回答三个问题：我是谁、当前有什么待处理、下一步该做什么。
- 客户侧只展示可公开的业务事实，不展示内部成本、供应商和员工隐私。

### 1.2 任务优先

- 每个页面只保留一个主任务：项目列表找项目、任务详情推进节点、验收页完成确认。
- 主操作固定使用品牌主按钮，次操作使用描边或浅底按钮，危险操作使用红色。
- 高频动作不藏在多级菜单中。

### 1.3 信息分层

- 第一层：页面标题、项目/客户名称、当前状态。
- 第二层：进度、日期、金额、负责人等关键事实。
- 第三层：说明、备注、辅助字段。
- 不使用整块强色背景承载多个层级信息。

### 1.4 一致性

- 颜色、圆角、间距、字号、阴影全部使用 `src/uni.scss` Token。
- 图标统一使用 `JzIcon`，禁止 emoji、字符箭头和散落 Unicode 图标。
- 同类状态使用相同语义色和相同文案格式。
- 页面跳转统一使用 `src/config/index.ts` 的 `P.*`。

### 1.5 可执行

- 表单字段必须说明用途，错误提示指出具体问题和修正方式。
- 空态必须提供下一步动作；无权限时解释原因，不只显示“无数据”。
- 列表必须支持下拉刷新；提交成功后返回来源页并刷新数据。

## 3. 字体与数字

### 3.1 字体族

```scss
-apple-system, BlinkMacSystemFont, 'Helvetica Neue', 'PingFang SC',
'Hiragino Sans GB', 'Microsoft YaHei', sans-serif
```

### 3.2 字号层级

| 场景 | Token | 建议字号 | 字重 |
| --- | --- | --- | --- |
| 页面大标题 | `$jzb-font-xl` | 42rpx | 700 |
| 卡片主标题 | `$jzb-font-md` / `lg` | 32-36rpx | 650-700 |
| 正文 | `$jzb-font` | 30rpx | 400-500 |
| 次级信息 | `$jzb-font-sm` | 26rpx | 400-500 |
| 辅助/标签 | `$jzb-font-xs` | 22rpx | 400-600 |
| 大数字 | 44-64rpx | 44-64rpx | 700-750 |

### 3.3 文本规则

- 金额、数量、百分比、日期使用更醒目的字重，但不使用过多装饰色。
- 标题最多两行；列表标题单行省略；说明文本最多两到三行。
- 不使用全大写英文标题。
- 文案使用业务语言，例如“等待业主确认验收”，不要使用“状态 3”。

### 4.4 阴影

- 普通卡片：`0 2rpx 8rpx rgba(15,23,42,.035)`。

- 浮出操作：`0 16rpx 38rpx rgba(14,138,125,.28)`。
- 不使用黑色厚重阴影；阴影只用于表达层级，不用于装饰。

## 4.5 层级（z-index）

唯一真源：`src/uni.scss` 的 `$jzb-z-*`。**禁止**在页面或组件样式里写裸数字。

| Token | 值 | 用途 |
| --- | --- | --- |
| `$jzb-z-content` | 1 | 同层装饰：头图内文字、卡片压边 |
| `$jzb-z-raised` | 10 | 局部抬升：页头栏、卡内下拉建议 |
| `$jzb-z-sticky` | 100 | 吸顶导航 / 分段 / 表头 |
| `$jzb-z-fixed` | 200 | 底部固定操作条、悬浮新增（FAB） |
| `$jzb-z-tabbar` | 300 | 自定义 TabBar |
| `$jzb-z-page` | 400 | 全屏页面层（CatalogPicker 等） |
| `$jzb-z-dropdown` | 500 | 锚定下拉浮层 |
| `$jzb-z-mask` | 1000 | 遮罩 |
| `$jzb-z-modal` | 1010 | 抽屉 / 模态面板 |
| `$jzb-z-confirm` | 1020 | 确认弹窗（必须高于抽屉） |
| `$jzb-z-popover` | 1050 | 高优先级说明气泡 |
| `$jzb-z-toast` | 1100 | 轻提示 |
| `$jzb-z-loading` | 1200 | 全局 Loading |

规则：

- 同层内需要再分先后时用 `$jzb-z-<name> + n`，不要另起数值。
- 任何浮层都不得使用 `999`/`9999` 之类的“保险值”。
- 新增浮层先选上表 Token，选不到再议新增，不允许就地写数字。

## 5. 页面模板

### 5.1 Tab 工作台

```text
状态栏安全区
品牌渐变 Header
角色与身份摘要
2 × N 指标卡
工作台快捷入口
风险/待办提醒
我的项目
最新动态
底部角色 TabBar
```

规则：

- 指标卡按 2 列排布，不强行塞入 4 列。
- 每个快捷入口必须有统一线性图标容器。
- 需要关注区域位于项目列表前，避免重要待办被淹没。

### 5.2 列表页

```text
自定义 Header（标题/总数/主操作）
搜索框
横向筛选 Chip
卡片列表
悬浮新增（有权限时）
底部 TabBar
```

- 筛选 Chip 默认白底描边，选中才使用浅品牌底。
- 列表卡片必须有明确标题、状态、核心元数据和一个主跳转方向。
- 列表为空时展示“为什么为空 + 下一步动作”。

### 5.3 详情页

```text
封面/主信息卡
状态与进度
关键事实区
待办横幅
分段导航
业务内容区
底部固定操作（必要时）
```

### 5.4 动作与按钮

按钮不是页面装饰，而是业务状态和下一步动作的可见承诺。所有新增页面按以下顺序判断动作形态：

1. **当前状态是什么**：空状态、进行中、待确认、已完成。
2. **这是不是当前唯一主任务**：只有唯一主任务使用品牌渐变主按钮。
3. **点击后会改变什么**：补充、创建、推进、确认、查看或危险操作必须用不同语气。
4. **失败或等待时怎么反馈**：必须有 loading、disabled、pressed 和失败恢复路径。

动作层级：

- **主任务入口**：使用 `JzActionCard` 的 `primary`，放在任务区顶部，全宽展示，说明为什么现在要做。
- **继续补充**：使用 `JzActionCard` 的 `subtle`，降低视觉权重，放在统计摘要下方，不与项目列表争抢注意力。
- **局部操作**：使用图标按钮、文字按钮或描边按钮，不占用主按钮。
- **危险操作**：只使用红色语义，不得与主按钮并排抢焦点。

硬性规则：

- 一个屏幕区域最多一个品牌渐变主按钮。
- 按钮必须说明动作结果，优先使用「继续录入项目」「建立承接任务，开始录入」这类动词短语。
- 按钮触控区不低于 `88rpx`；图标与文本间距、按压态、禁用态必须统一定义。
- 空状态必须同时给出“为什么为空 + 下一步动作”，不能只留一个孤立的按钮。
- 列表工具栏不得承载主创建动作；主创建动作必须进入任务引导区或专用动作条。

业务承接页的「录入项目」是首个样板：无项目时使用主任务行动卡，已有项目时降级为「继续录入」行动卡。客户列表和项目列表的空状态已按同一规则接入：空数据时用主任务行动卡替代孤立按钮，已有数据时保留悬浮或 Header 辅助动作。财务录入已使用动作结果命名；履约任务、验收整改、材料到场、阶段开工和项目结算已使用明确图标与业务动作文案。

确认弹窗规则：

- 确认动作统一通过 `confirmAction` / `confirmDanger`，不得在业务页面重复手写确认颜色和文案。
- 标题必须是具体动作，例如「关闭项目结算」，不能只写「提示」。
- 正文必须说明结果和不可逆影响。
- 确认按钮必须重复动作结果，例如「确认删除」「关闭结算」「确认释放」。
- 删除、关闭、资金释放、停用等高风险动作统一使用 `confirmDanger`，确认按钮使用危险色。
- 卡片内「登记收款」「安排付款」「更换」「指定」等文字入口必须升级为可点击的动作胶囊，不能保留无按压反馈的裸文字。

输入弹窗规则：

- 需要输入名称、金额、原因等短文本时使用 `JzInputDialog`，不得使用原生可编辑 `showModal`。
- 必须展示字段标签、用途说明、占位示例、校验错误、取消和确认动作。
- 确认按钮在输入为空或提交中必须禁用，并显示处理中状态。
- 标签重命名、套餐分区新增/重命名、合同变更金额与原因、接管计划调整原因均已迁移；后续仅在确有复杂表单需求时新增专用弹窗。

- 项目详情头图必须有遮罩，保证白色标题可读。
- 状态标签不覆盖关键信息。
- 重要动作放在上下文附近，而不是全部放在页面底部。

### 5.5 表单页

```text
页面标题与说明
分组表单卡
字段说明/错误
固定底部主按钮
安全区
```

- 数字输入右对齐，文本输入左对齐。
- 选择器统一“当前值 + 右侧箭头”。
- 必填字段只对真正影响业务完整的字段展示星号。
- 提交中禁用按钮并显示 Loading，避免重复提交。

### 5.6 验收/确认页

```text
验收对象与结果
验收说明
整改项
影像证据
提交/确认人信息
底部双动作或单主动作
```

- 业主确认页的主操作必须明确：“确认验收”和“有异议，驳回”。
- 驳回后保留现场事实，不允许覆盖历史记录。

## 6. 组件规范

### 6.1 顶部 Header

组件：`JzPageHeader`

- 自定义导航页必须使用状态栏安全区。
- 标题 42rpx / 700，副标题 26rpx。
- 右侧操作使用半透明胶囊按钮，支持文字或 `JzIcon`。
- 页面内不再重复绘制第二个标题栏。

### 6.2 底部 TabBar

组件：`JzTabBar`

- Tab 由 `ROLE_TABS` 按角色返回。
- 图标 42rpx，标签 20rpx。
- 激活项使用浅品牌底图标容器，不只改变文字颜色。
- 始终保留底部安全区。

### 6.3 卡片

- 标准卡片使用白色背景、20rpx 圆角、轻边框和轻阴影。
- 卡片内不能嵌套无边界的大卡片。
- 列表卡的可点击区域必须覆盖整个卡片。
- 卡片状态变化使用左侧色点、状态标签或进度条，不整卡变色。

### 6.4 按钮

| 类型 | 使用场景 |
| --- | --- |
| `jz-btn--primary` | 当前页面唯一主操作 |
| `jz-btn--plain` | 次级操作、轻量确认 |
| `jz-btn--ghost` | 取消、补充操作 |
| `jz-btn--neutral` | 中性操作 |
| `jz-btn--text` | 低优先级文字动作 |
| `jz-btn--danger` | 删除、驳回、风险操作 |

交互：

- 点击按下缩小不超过 1.5%。
- 禁用态透明度 48%，不触发点击。
- 加载态保持原宽度，不因文案变化产生页面跳动。

### 6.5 表单

- 输入框背景 `$jzb-bg-hover`，聚焦时白底 + 品牌描边。
- 标签宽度 150-176rpx。
- 错误信息紧邻字段下方，使用 22rpx 红色文本。
- 图片上传最多九张，删除按钮固定右上角。

**选值控件（强制）**

- 枚举 / 日期 / 时间选择**禁止**再手写 `<picker><view>…` 结构，统一使用 `JzSelectField`。
  - `variant="plain"`：与 `jz-form-row` 同排，右侧值 + 下箭头，无底色（默认）。
  - `variant="boxed"`：独立字段区，浅底卡片，用于抽屉或整块表单。
  - 三种模式：`selector`（枚举）/ `date` / `time`；`@change` 直接回传值，页面内不再写 `$event.detail.value`。
  - 图标必须在 `picker` 内部，保证整块可点。
- 计划起止日期统一使用 `JzDateRangeField`，禁止两个独立日期 picker。
- 上传类字段统一使用 `FileUploadField`，图片必须支持预览。

**表单分区与校验**

- 必填项以 `*` 标注，校验失败时保存按钮禁用并给出行内错误，不以 toast 作为唯一反馈。
- 保存中禁止关闭承载容器（抽屉 / 弹窗），防止半提交。

### 6.5.1 表单承载选型

| 场景 | 承载 |
| --- | --- |
| 独立表单页（有页面头 + 底部提交条） | 页面内 `jz-card` 表单卡 |
| 列表页的「新增 / 编辑一项」 | `JzSheet` 底部抽屉 |
| 仅修改一两个字段 | `JzSheet` 底部抽屉 |
| 需要填写原因/依据后确认 | `JzInputDialog` 或 `JzConfirmDialog` 的 editable 模式 |

**禁止**在列表页顶部常驻编辑表单卡；新增入口使用 `JzFloatAdd`，修改入口放在列表项内。

### 6.10 浮层与弹窗

| 组件 | 用途 | 规范 |
| --- | --- | --- |
| `JzSheet` | 底部半屏抽屉：表单、列表选择、多步录入 | 遮罩 `rgba(15,23,42,.45)`、`z-index:200`、28rpx 上圆角、0.3s 滑入；内容区 `max-height` 默认 70vh，超高表单传 `max-height="92vh"` |
| `JzConfirmDialog` | 居中模态确认：删除、驳回、资金相关、不可逆动作 | 240rpx 遮罩 + `z-index:300`；危险动作图标底 `$jzb-danger-soft`、主按钮 `jz-btn--danger`；支持 `editable` 填写原因；同一时刻只允许一个 |
| `JzActionSheet` | 动作选择面板 | 基于 `JzSheet`，选项 index 固定，危险项 tone 收敛 |
| `JzInputDialog` | 单字段文本输入 | 基于 `JzSheet`，空值禁用确认 |

**抽屉内滚动区（强制，2026-10-10 修复）**

- 抽屉内需要「内容滚动 + 底部按钮常驻」时，外层 flex 容器必须给**确定高度**：
  `height: calc(70vh - 32rpx)`；抽屉若传了 `max-height="92vh"`，则用
  `height: calc(92vh - 32rpx)`。
- 滚动子元素写 `flex: 1; min-height: 0;`，**不要写 `height: 0`**。
- 反例（会导致字段穿到底部按钮下方）：外层只写 `max-height`，子元素写
  `flex:1; height:0` —— 父容器没有确定高度时，小程序 `scroll-view`
  建立不起 `scrollHeight`，内容不裁剪。
- 内容较短（不滚动）的抽屉改用普通 `view` + `max-height`，不要放 `scroll-view`。
- 自检：`wx.createSelectorQuery().select('.xxx').fields({scrollOffset:true,size:true})`
  应满足 `scrollHeight > height` 且底部操作区 `top ≈ 滚动区 bottom`。

**强制**

1. 禁止在页面内手写 `mask + sheet` 结构；浮层必须走上述组件。
2. 禁止使用 `uni.showModal` / `uni.showActionSheet`；确认动作走 `confirmAction` / `confirmDanger` / `promptText` / `alert`，动作面板走 `JzActionSheet`。
3. 确认弹窗宿主 `<JzConfirmDialog />` 必须挂在**调用确认的页面模板内**（页面级宿主）。
4. 危险动作必须用 `tone: 'danger'`，确认文案与业务结果一致，禁止默认「确定」。
5. 有前置条件的入口（未首联、无量房、无方案等）必须用阻断模态说明**缺什么 + 去哪里补**，不能只用 toast。

### 6.6 状态标签

组件：`JzTag`

- 浅底标签用于普通状态。
- 实底标签只用于关键状态，例如当前阶段、最高优先级。
- 标签可带 10rpx 状态点。
- 标签文本使用业务状态，不使用编号。

### 6.7 空态

组件：`JzEmpty`

- 图形容器 128rpx，使用统一 `inbox` 图标。
- 主文案解释“当前没有什么”，副文案解释“如何产生数据”。
- 有权限时在空态中提供主操作按钮。

### 6.8 进度

组件：`JzProgress`

- 默认高度 10rpx，详情页可 12-14rpx。
- 品牌进度默认使用轻渐变。
- 进度值必须同时展示数字，不只展示颜色。

---

### 6.9 骨架屏

组件：`JzSkeleton`

- 列表首次加载时展示 3-4 条骨架，不使用整页 Loading。
- 已有数据刷新时保留内容，避免页面闪烁。
- 骨架尺寸与真实卡片一致，减少布局跳动。

## 7. 图标系统

组件：`JzIcon`

- 统一 24 × 24 视口、线性风格、圆角端点。
- 默认描边 1.8；激活态 2.2；小尺寸图标不低于 1.6。
- 常用尺寸：22 / 24 / 28 / 34 / 42rpx。
- 图标颜色使用语义 Token，不随意使用多色。
- 禁止 emoji、字符加号、字符箭头和 Unicode 勾选符号作为正式 UI 图标。
- 图标必须有文字、标签或可访问名称，不单独表达关键业务含义。

## 8. 交互规范

### 8.1 点击反馈

- 可点击卡片：按压缩放至 98.8%-99.2%。
- 按钮：按压缩放至 98.5%，透明度轻微降低。
- 列表项：按压背景变为 `$jzb-bg-hover`。
- 动画时长 0.15-0.35s，不使用弹跳式夸张动画。

### 8.2 加载

- 首屏加载使用骨架屏，不使用整页转圈。
- 表单提交使用按钮 Loading + 禁止重复点击。
- 上传进度可展示百分比；无进度能力时展示“上传中”。

### 8.3 反馈

| 场景 | 反馈方式 |
| --- | --- |
| 轻量成功 | Toast |
| 表单字段错误 | 字段下方错误文本 + 保存禁用 |
| 不可逆操作 | `JzConfirmDialog`（danger）二次确认 |
| 需填原因/依据 | `promptText`（`JzConfirmDialog` editable）|
| 前置条件不满足 | 阻断模态：说明缺口 + 恢复路径 |
| 纯信息说明 | `alert`（单按钮）|
| 网络失败 | 页面错误态 + 重试按钮 |
| 权限不足 | 解释原因并返回来源页 |
| 业务状态冲突 | 显示服务端业务提示，不自行猜测 |

**禁止**用 Toast 承载需要用户确认、补录或理解的阻断信息；Toast 只做轻量结果反馈。

### 8.4 导航

- Tab 切换保留当前角色 Tab 顺序。
- 详情返回后刷新来源页关键数据。
- 项目详情、任务详情、验收页之间保持稳定返回路径。
- 页面跳转统一使用 `P.*`，禁止手写路由字符串。

## 9. 状态设计

### 9.1 状态覆盖

每个核心页面必须覆盖：

```text
正常
加载中
空数据
无权限
请求失败
提交中
提交成功
提交失败
业务状态冲突
```

示例：

- 项目列表为空：说明当前没有项目，BOSS/设计师显示“新建项目”。
- 项目列表失败：显示“加载失败，点击重试”。
- 验收页无权限：显示“当前身份无验收操作权限”。
- 提交验收失败：保留表单内容，允许重试。

### 9.2 状态语义色板（唯一真源）

业务状态标签**只**使用 `STATUS_COLOR`（TS）与 `$jzb-status-*`（SCSS），
禁止在页面或 `domains/*/meta.ts` 内写裸色值。

### 9.3 各业务域状态对照

| 域 | 状态 → Tone |
| --- | --- |
| 项目 `ProjectStatus` | `preparing`→todo、`ongoing`→品牌 primaryBase、`suspended`→pending、`accepting`→special、`finished`→done、`settled`→dark |
| 阶段 `StageStatus` | `todo`→idle、`doing`→品牌、`accepting`→pending、`done`→done、`overdue`→blocked |
| 任务 `TaskStatus` | `todo`→todo、`doing`→品牌、`accepting`→pending、`done`→done、`overdue`→blocked |
| 验收 `AcceptResult` | `pass`→done、`rectify`→pending、`reject`→blocked |
| 收款 `ReceivableStatus` | `pending`→todo、`partial`→pending、`received`→done、`overdue`→blocked、`closed`→text4 |

### 9.4 使用规则

1. 状态标签必须「颜色 + 文字」，禁止只用颜色表达状态。
2. 品牌色 `primaryBase` 表示**进行中**，与 `done` 绿（已完成）严格区分。
3. 金额与风险等级使用 `TOKEN_COLOR.success / warning / danger`，**不复用**状态色板。
4. 新增业务状态必须先在 §9.2 选定一个 Tone，**不得新增色值**。
5. `src/domains/<域>/meta.ts` 是状态文案与颜色的唯一定义处，页面不得内联状态色。

## 10. 内容与文案

- 使用简洁业务语言，不写开发术语。
- 主标题不超过 16 个中文字符。
- 按钮使用动词短语：“提交验收”“保存客户”“开始阶段”。
- 空态文案包含下一步：“等待装修公司发送业主邀请”。
- 金额单位统一显示“元”或“万元”，不混用。
- 日期显示优先 `MM-dd`；跨越年份时显示 `YYYY-MM-dd`。

## 11. 无障碍与可用性

- 正文和背景对比度满足基本可读性。
- 关键状态不能只依赖颜色，必须同时使用文字。
- 点击区域建议不小于 88rpx × 88rpx。
- 图标按钮需要文字或 `aria` 语义（微信小程序侧使用可识别文本）。
- 表单支持系统字号放大后不遮挡主操作。
- 图片必须有有效 URL；加载失败时保留灰色占位。
