> 更新时间：2026-09-15
> 范围：`th4-decoboon-app`
> 构建目录：`dist/build/mp-weixin`

## 1. 改造前基线与失败原因

改造前 `src/pages.json` 只有一个 `pages` 数组，60 个页面全部属于主包。重新执行生产构建后，主包候选体积为：

- 总文件体积：1,057,499 B / 1,009 MiB
- 页面目录：约 1,340 KiB
- 公共组件目录：约 336 KiB
- 主要热点：首页、报价详情、项目详情、个人业绩、设计方案、客户详情

结论：当前构建尚未真正超过 2MB，但 60 页、所有业务域和全部静态依赖都堆在主包，已经没有可持续扩展空间。分包改造解决的是“结构性超限风险”和后续按需加载能力，不是压缩一次构建产物。

## 3. 公共依赖处理

- `HouseCard`、`SalesSteps` 仅客户分包使用，已下沉到 `subpackages/customer/components`。
- `DesignEditorSheets` 仅设计分包使用，已下沉到 `subpackages/design/components`。
- `CatalogPicker` 同时被设计和报价页面使用，保留在 `src/components`。
- `billing`、`supply` 领域模块仅各自分包使用，已下沉到对应分包私有目录。
- `property` 虽然客户页面直接使用，但被 `design/project/trade` 共享领域 API 依赖，继续保留在 `src/domains/property`，避免主包反向依赖客户分包。
- 当前没有配置独立分包。所有分包都依赖主包登录态、HTTP 和全局组件，强行设置 `independent: true` 会破坏运行时依赖。
- `src/static` 当前无文件，因此没有静态资源迁移；分包 `static` 目录已按模块预创建，后续只放该域的小体积资源。

## 4. 预下载策略

`src/pages.json.preloadRule` 已配置：

- 首页 WiFi 下预下载客户、项目、设计、报价。
- 项目 Tab 随所有网络预下载项目包。
- 客户 Tab 随所有网络预下载客户包。
- 动态 Tab 随所有网络预下载消息包。
- 我的 WiFi 下预下载企业、团队、业绩、订阅。
- 财务 Tab 随所有网络预下载财务和统计。

- 最大单分包：152,288 B / 148.7 KiB / 0.145 MiB

- 分包：11 个，共 50 页

## 6. 自动验证

```bash
npm run type-check
npm run build:mp-weixin
npm run check:subpackages
```

或一次执行：

```bash
npm run verify:mp-weixin
```

微信开发者工具仍需人工验证：

1. 导入 `dist/build/mp-weixin`。
2. 详情 → 本地代码 → 代码依赖分析，确认无缺失模块、无主包到分包私有引用。
3. 逐个切换角色，验证六个自定义 Tab。
4. 从每个 Tab 进入对应分包详情页，再返回，验证预下载和页面栈。
5. 验证登录、企业创建、邀请加入、订阅回跳和 401 重登录。
6. 上传体验版，在真机弱网、WiFi、冷启动和二次进入场景验证。

## 8. 风险与人工确认

- 微信开发者工具的“代码依赖分析”是最终发布口径；当前仓库体积脚本只能做构建产物兜底检查。
- 自定义 Tab 不应改成原生 `switchTab`，除非同步迁移 `ROLE_TABS` 并增加原生 `tabBar` 配置。
- `preloadRule` 的 `network: "all"` 会增加流量消耗，上线后应结合真实埋点调整。
- 上传前仍需人工检查备案、隐私协议、用户隐私保护指引、服务类目、位置权限用途和后端域名。
- 新增分包时必须同步更新 `pages.json`、`P.*`、预下载规则和 `AGENTS.md` 中的拓扑表。
