# 项目经理视角业务闭环与强交互

> 角色：`Pm`（项目经理）  
> 小程序：`th4-decoboon-app`  
> 后端：`th4-decoboon`  
> 数据边界：当前企业 + 当前员工负责的项目域

## 1. 角色边界

项目经理负责报价转项目后的施工履约，不负责获客、客户转交和报价编辑。项目经理的全部业务对象由 `Project.manager` 反向确定：

```text
当前员工
→ Project.manager = 当前员工
→ 项目、阶段、任务、日报、验收、材料
→ 项目关联客户
→ 项目来源报价
→ 当前员工的业务通知
```

服务端强制规则：

- 项目列表仅返回 `com_id + manager_id` 命中的项目。
- 客户、跟进和报价不能按客户负责人/报价创建人套用 `Self`，必须通过 `ProjectManagerAccessContext` 从负责项目反向校验。
- 阶段、任务、现场动态、验收和材料必须通过 `ProjectAccessContext.requireVisible`。
- 项目经理可以调整施工计划、推进任务、提交验收和推进材料状态，但不能修改客户归属、创建/推进报价、邀请员工或转为项目。
- 当前企业、当前员工、项目归属和任务归属全部以服务端重新加载的数据为准，不接受前端伪造参数。

## 3. 邀请注册闭环

1. 企业负责人使用 `18660219918 / 123456` 登录。
2. 进入「我的 → 邀请员工加入」或工作台「邀请成员」。
3. 选择「项目经理」，填写未被注册的手机号。
4. 分享邀请链接；被邀请人打开邀请页，填写姓名和密码。
5. `user/accept` 校验邀请状态和有效期，创建 PM 员工并复制邀请人的企业、门店和团队归属。
6. 被邀请人登录后，`user/info` 返回企业、门店、团队和 `Pm` 角色。
7. 企业负责人在项目详情/项目创建中将该 PM 指定为项目负责人。
8. PM 工作台出现对应项目，客户、报价和履约数据按项目负责人范围进入视图。

## 4. 履约业务闭环

```text
企业负责人指派项目经理
→ PM 工作台出现负责项目
→ 核对来源报价与客户信息（只读）
→ 查看/调整施工计划
→ 阶段开工
→ 推进任务并完成节点留证
→ 发布现场动态和日报
→ 材料按计划到场
→ 阶段任务完成
→ PM 提交阶段验收
→ 业主确认或驳回整改
→ 项目进度刷新
→ 项目完工并沉淀交付业绩
```

### 4.1 开工与任务

- 阶段 `Todo → Doing` 仅允许 Boss/Pm，开工后生成业主可见的开工动态。
- 任务 `Todo → Doing → Accepting → Done` 由 PM 推进，隐蔽工程必须先完成节点留证。
- 任务状态变化自动刷新阶段和项目进度，前端不直接修改派生进度。

### 4.2 现场与材料

- 现场动态作者固定为当前 PM，企业固定为项目企业。
- 日报、图片和问题记录进入项目动态时间线，并可按业主可见性同步。
- 材料计划按项目范围读取，只有 Boss/Pm/Purchaser 可推进；项目经理重点处理延迟风险。

### 4.3 验收

- 阶段任务完成后由 PM 提交验收。
- 业主确认后阶段完结，驳回后进入整改并允许重新提交。
- 验收通过率、驳回数量和待确认数量进入 PM 履约业绩。

### 4.4 消息与业绩

项目经理消息范围：

- 本人负责项目的进度提醒。
- 本人项目下的逾期任务。
- 本人项目收到的验收、材料和系统通知。

项目经理业绩指标：

- 在管项目、施工中、待验收、停工、逾期项目。
- 待办任务、施工中任务、逾期任务。
- 今日动态、近 7 天动态。
- 合同额、已完成交付额、平均进度。
- 准时交付率、验收通过率。
- 关联客户数、来源报价数、材料风险数。

## 6. 强交互规则

- 首页和驾驶舱的每个风险数字都可进入对应项目、任务、阶段、客户或报价。
- 项目、任务、验收和材料按风险优先排列，逾期数据使用危险色并始终高于普通数据。
- 列表包含加载态、空态、错误态和下拉刷新；网络失败不伪装成空数据。
- 阶段开工、任务完成、节点确认、材料到场和验收提交成功后重新拉取服务端数据。
- 客户和报价对 PM 只读，页面不展示编辑/报价推进动作；即使伪造请求也会被服务端拒绝。
- 不返回无关企业、门店、团队和成本字段，减少懒加载 SQL 与信息泄露。

## 7. 验收路径

1. 企业负责人登录 `18660219918 / 123456`，邀请项目经理并完成接受注册。
2. 为 PM 创建/指派一个已接受报价生成的项目。
3. PM 登录后检查工作台、项目、客户、报价和履约驾驶舱只出现本人项目数据。
4. 在项目详情调整计划、推进任务、发布日报、提交阶段验收。
5. 在驾驶舱核对任务风险、材料风险、验收和履约业绩。
6. 在企业端确认通知、验收和项目进度同步更新。
7. 使用其他企业或其他 PM 账号访问同一 `customerId/quoteId/projectId`，预期返回 403/404 且不泄露数据。
